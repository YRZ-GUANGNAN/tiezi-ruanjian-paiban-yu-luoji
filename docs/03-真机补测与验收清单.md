# 小红书手机端非购物功能：真机补测与验收清单

整理日期：2026-10-13（Asia/Shanghai）。共 **100 项原始用例**，保留各项完整操作与分支要求。后续已在魅族 21 的 8.72.0 上补测：**31 项获得部分观察，69 项待执行，0 项宣称完整覆盖全部原定分支**。逐项状态、证据和未覆盖内容见[实测覆盖与待补测](新版研究/06-实测覆盖与待补测.md)，实际行为见[真机实测](新版研究/04-魅族21真机实测.md)。没有开始制作复刻 App。

范围：内容浏览、图文和视频笔记、搜索、创作、个人页、收藏、社交、非交易直播、设置、权限和其他非购物能力。商城、购物车、订单、支付、付费礼物、带货成交、商业投放全部排除。

## 1. 执行顺序与统一记录

先执行 D001–D009 固定版本、账号与权限条件；随后完成笔记浏览、互动、搜索、发布草稿等主链路；消息、直播和长尾功能按入口及测试条件补测。每条用例从“入口存在性”开始，未发现入口要记录“本版本/本账号未见”，不能写成整个产品不支持。

每次执行至少填入下列记录，表中“专门记录”是在此基础上追加：

| 记录项 | 内容 |
|---|---|
| 执行身份 | 用例 ID、执行日期时间、执行人、测试轮次；账号仅记录别名 A/B 及与功能有关的条件 |
| 环境基线 | Android/iOS、系统版本、设备型号、屏幕像素与显示缩放、方向、App 版本与构建号、安装来源 |
| 状态前提 | 冷/热启动、登录状态、关注关系、权限、通知设置、网络、是否前后台切换；已知实验入口差异 |
| 输入和入口 | 测试素材/公共内容编号、页面路径、输入词、点击/长按/滑动位置与次数；不记录密码、令牌和真实私聊内容 |
| 观察时间线 | 操作前画面 → 输入时刻 → 即时反馈 → 稳定结果 → 返回/重进后的状态；失败或中断也保留 |
| 证据 | 录屏、必要截图、可取得的页面层级、相关系统设置截图；每个文件带用例 ID、版本与轮次 |
| 结果 | 待执行 / 已观察 / 未出现入口 / 条件不足 / 与旧包不同 / 需复测；填写实际现象，不能仅填“通过” |
| 后续规格 | 哪条研究结论得到支持、被修正或仍未知；复刻是否采用另行决定 |

计时用录屏帧数与时间戳估计，记录录屏帧率和误差。不要用主观“很快”代替数值，也不要把录屏估值当作原 App 内部计时参数。动作完成后至少检查一次返回或重进；需要确定持久化时再增加重启条件。输入失败、网络失败与权限拒绝分别记录，不能合并为单一“错误”。

建议准备自制图片、长宽比不同的图片、短视频、无敏感内容的测试文本，以及适量可公开浏览的内容。涉及发布、关注/点赞/收藏、评论、发消息、群管理、开播、举报提交等写入用例，后续仅使用已获授权的测试账号和测试对象执行；其中发送消息需要用户明确授权。当前未获授权或条件不足的条目继续标记待执行，不用真实联系人或真实内容补齐结果。

## 2. 版本对照与证据边界

| 基线 | 已知信息 | 补测用途 |

| 新版 Android 包与商店资料 | 应用宝 `9.49.1 / 9491803` 安装包已取得，2026-10-03 更新 | 静态对照资料，不代表已在手机运行；来源见新版研究目录 |

| 当前实际测试版 | MEIZU 21；Android 16；`8.72.0 / 8720916`；1080×2340、440dpi；来源记录 `com.meizu.mstore` | 用户选择先测已装旧版；相同用例的版本差异分别保留，签名待验证 |

原 App 行为观察与复刻验收分两列保存：前者回答“在这个版本与条件下实际发生了什么”；后者回答“独立实现是否满足最终采用的规格”。不要求复刻继承旧版异常，不以功能相似推定内部代码、服务端算法或数据库相同。

本轮需特别核对的静态线索：

- `NoteFeed` 存在 `liked/likedCount`、`collected/collectedCount`、`commentsCount`、`imageList`、`videoV2`；字段存在不证明按钮反馈、网络时序或持久结果。
- 评论模型存在 `rootCommentId`、`targetComment`、`subComments`、`subCommentCursor`、`likeCount`、`liked`、`isSendSuccess`、`retryCount`；待核对 UI 层级、分页和失败重试的实际对应关系。
- 关注流响应存在 `cursor/hasMore`；待核对末页、刷新与返回行为，不能据此声称服务器一定不重复返回。
- 旧包图片详情 `NoteDetailImageDisplayPresenter.m7` 配置横向 `RecyclerView`、`PagerSnapHelper`、缓存数 3、关闭 change animation；拖动时页码透明度以 200ms 变为 1，`t7(5000)` 延时路径后以 200ms 变为 0。这些仅是特定代码路径的配置，需通过 D021、D022、D091 核对可见效果和是否启用。
- 旧包 V3 详情按钮订阅路径存在重置赞/收藏状态与计数的代码，普通用户是否启用不明；视频按钮还有独立实现。通过 D038、D039、D040 比较实际版本与内容类型，不把该异常照搬为复刻要求。
- 用户收藏专辑 `board` 与作者笔记合集 `Collection/Portfolio` 是不同研究对象。D071–D074 检查前者，D075 检查后者，分开记录入口、归属与权限。

## 4. 观察结果如何转成复刻验收

完成实测后，按下表保存结论，避免把“研究中猜测”直接变成开发要求。

| 情况 | 研究记录方式 | 后续独立实现处理 |
|---|---|---|
| 同版本、同条件可重复出现 | 链接录屏和执行记录，写明前提、输入、结果、异常分支 | 将采用的行为写入页面事件规格，再用相同输入验证实现 |
| 旧包静态路径与真机不同 | 同时保留代码事实和手机现象，标为版本/分支不一致 | 以目标版本的实际产品行为与用户选择为依据，不盲目复制旧实现 |
| 只有官方声明、未找到入口 | 保留功能声明与实测账号条件，标记入口未见 | 作为可选研究项；不承诺与全部小红书账号完全一致 |
| 只有复刻实现建议 | 清楚标为自研方案，例如稳定分页、失败回滚或本地草稿机制 | 用自研规格验收；不能称为原 App 内部实现 |
| 涉及服务端不可见逻辑 | 记录可见输入输出及限制；推荐权重、审核阈值、数据库保持未知 | 自行设计并标注选择，不使用“已逆向还原算法”的表述 |
| 操作条件或授权不足 | 标记条件不足，保存已完成的只读观察 | 不用模拟成功或推测结果补充完成度 |

每个进入开发的页面至少要有：入口和退出、数据为空、加载中、已有内容、错误与重试、权限/登录拦截（如相关）、返回恢复、快速重复输入、后台恢复。对写入能力再加成功、失败、撤销/取消、跨页面一致性与重进后状态。以上是独立实现的验收建议，不宣称小红书原 App 已逐项符合。

## 5. 完成度与补测退出标准

本文件覆盖 13 个分组、100 项用例。当前 31 项有部分观察、69 项待执行，完整原用例覆盖仍为 0；已有 30 条具体交互结论可供复刻参考。不得把清单条数、观察次数或入口数量作为“已还原功能数”，也不提供整 App 完成百分比。

一次实测阶段结束时，应交付实际版本信息、每条结果状态、证据目录、差异记录和更新后的页面规格。核心用例需要覆盖至少一个正常路径和一个相关失败/返回路径；入口未出现、条件不足和服务端未知事项单列保留。iOS 和 Android 各自验收，不因一端通过就认为另一端相同。

若只具备单台设备，先完成浏览、权限、图片视频、搜索、草稿和导航；跨账号关系、私信收发、群管理和直播连麦保留独立待测项。未来补测无需重做本轮已保存的静态证据与官方资料，只在出现版本差异或证据矛盾时定向更新。

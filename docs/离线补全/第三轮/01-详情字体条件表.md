# 详情字体：默认、条件覆盖与品牌字重

以下来自同一份 Android 8.72.0 安装包。第二轮的 XML 默认仍有效；本轮确定的是另一条有条件的字体覆盖路径。运行开关、当前字号档位和热补丁没有采到。

## 属性已精确对应

[FR207 原始指令](auxiliary/FR207-font-style-and-map-instructions.json)显示 `i69.j.V0` 是长度 1 的属性数组，唯一元素为 `0x7f040761`；字段 `i69.j.W0` 为索引 0。[FR208 二进制 XML 属性解析](auxiliary/FR208-detail-attribute-identities.json)确认 `res/Oo5.xml` 的标题控件给该属性赋值 3，正文赋值 10。

因此，第二轮暂时保留的“未知自定义属性 3/10”现在可以确认为这两个控件的字体 Token 输入，不是最大行数。[属性资源](auxiliary/FR205-token-attribute-resource.json)也将它定义为含 0–36 值的枚举。资源名经过混淆，结论依靠数值 id，而非补猜属性名称。

[FR204 枚举指令](auxiliary/FR204-token-enum-instructions.json)确定基础枚举 `s69.f` 有 37 项；扩展枚举 `s69.g` 有 111 项。序号 3 是 `T1`，序号 10 是 `B2LooseSwitch`。源码表 [F207](evidence/F207-token-map-init.java.txt)与 DEX 常量构造逐项比对 111 项，数值一致。

## 先判断是否覆盖

详情子类的条件为 `wq1.i.n1() || wq1.i.o1()`，见第二轮 F126 / FR114。本轮补全：

- [F201](evidence/F201-note-token-gate-n1.java.txt)：`n1()` 的未补丁默认返回 `false`。
- [F202](evidence/F202-note-token-gate-o1.java.txt)：`o1()` 先检查 `or1.b.d()`；该条件为真时返回 `false`，否则从 `ln.g.c().g(...)` 读取 `android_text_token_optimization_exp`，传入缺省值 `Boolean.FALSE`。
- [F213](evidence/F213-token-guard.java.txt)：前置检查使用列表包含关系，实际列表和当前对象仍未知。本轮没有证明配置来自哪台服务、运行时是否命中，不能把缺省 false 写成所有用户都关闭。

当两个条件均为假时，不经这个构造器 Token 路径覆盖，第二轮已恢复的 XML 值为标题 **16sp / bold / 附加行距 5.5dp**，正文 **15sp / normal / 附加行距 5dp**。这里的附加行距不是完整行高；其他后续代码仍可能改变控件。

## 开启覆盖后的条件表

[F208](evidence/F208-token-mode-read.java.txt)读取 SharedPreferences 文件和键 `font_size_setting`，缺省为 `-1`；[F215](evidence/F215-token-mode-bridge.java.txt)确认省略 Context 时使用存下的应用 Context。下面的“模式”是内部整数，不等同于已经确认的设置页面文案。

| 模式 | 索引变化 | 标题字号 / Token 行高 | 正文字号 / Token 行高 | 单位 |
|---|---|---|---|---|
| `-1`，读取缺省 | 不偏移 | 18 / 26 | 15 / 22 | sp |
| `0` | 不偏移 | 18 / 26 | 15 / 22 | dp |
| `1` | 加 37 | 20 / 29 | 17 / 25 | dp |
| `2` | 加 74 | 22 / 32 | 19 / 28 | dp |

[FR202 原始指令](auxiliary/FR202-token-apply-instructions.json)明确区分 `1`、`2` 的跳转和偏移，消除了第二轮 F124 反编译重复块带来的索引歧义。其他整数在这段代码里使用基础索引及 dp，但未证明设置界面允许存入其他值。

字号通过 `setTextSize` 设置，行高先按相应单位换算，再作为整数交给 `s69.h` 行高 Span。上表是 Token 输入，不是截图文字框的像素高，也不是对全部字体度量的复原。系统字号缩放与应用内档位是不同输入；sp 分支和 dp 分支不可互换。

标题基础 / 大 / 更大三项内部名分别为 `T1`、`T1Xlarge`、`T1Xxlarge`；正文为 `B2LooseSwitch` 及对应后缀。后缀仅作代码定位，不推定产品文案。第二轮已经核验的绑定字距 `0.015em` 不在本轮改写。

## 字重会按品牌分类

[F214 选择顺序](evidence/F214-token-weight-select.java.txt)、F216–F229 的委托方法，以及 [F230 字符串匹配](evidence/F230-platform-match.java.txt)组成以下未补丁路径。精确帮助器拥有者 `p69.l` 由 [FR206](auxiliary/FR206-weight-helper-references.json)确认。

| 字重数组索引 | 条件，按表中优先级 | 标题基础 / 大 / 更大 | 正文三档 |
|---|---|---|---|
| 6 | Android API < 29，优先于品牌 | 700 / 700 / 700 | 400 |
| 0 | huawei | 700 / 500 / 700 | 400 |
| 1 | honor | 600 / 600 / 600 | 400 |
| 2 | xiaomi、meitu 或 redmi | 450 / 450 / 450 | 305 |
| 3 | oppo、realme 或 oneplus | 500 / 500 / 500 | 400 |
| 4 | vivo | 600 / 600 / 600 | 400 |
| 5 | 其余匹配结果 | 600 / 600 / 600 | 400 |

品牌条件检查 `Build.MANUFACTURER` **或** `Build.BRAND`，按 `Locale.ENGLISH` 转小写后比较，未做任意机型逐一匹配。不能仅凭“魅族手机”就声称本轮观察到了索引 5。

数值字重仅在相应字体路径中应用；其他路径由字体帮助器处理内部样式码。API 28 以下还有按 `>500` 转换成粗体/常规的兼容分支。标题内部样式码为 2、正文为 0，不能把码 2 直接套作 `Typeface` 同名常量。专用数字字体不代表所有正文都使用同一字体资产。

完整条件、六个目标 Token 的数组、DEX 构造位置和原件摘要见 [font-condition-table.json](font-condition-table.json)。本轮确认了打包策略，仍未完成最终字体文件、当前实验配置和多品牌视觉验收。

# 第三轮：字体条件与评论排版

本轮补齐了详情字体的条件表，并把普通评论的资源、绑定代码与此前魅族 21 的几何记录联系起来。研究对象仍是 Android **8.72.0 / 8720916**，只覆盖非购物功能；没有开发软件，也没有新增真机或模拟器操作。

## 有用的新结论

| 问题 | 本轮得到的结果 | 证据边界 |
|---|---|---|
| 标题、正文为何可能不是固定字号 | 详情字体覆盖有条件开关，开启后按本地字号档位选择参数；标题三档 18/20/22，正文 15/17/19，行高另表 | 单位由档位决定，不能省略条件称为最终字号 |
| 不同品牌是否有专门处理 | 字重索引按 Android 版本、制造商或品牌选择；已定位七个索引的条件 | 是打包字重策略，不是所有机型视觉验证 |
| 回复为什么比一级评论更靠右 | 一级正文起点 57dp，二级正文起点 82dp；差 25dp | 所选普通布局的静态几何；与旧真机 157/226px 起点一致 |
| 评论作者、正文、时间有何层级 | 打包默认为作者 13sp、正文 14sp、时间/回复 Span 12sp、赞数 11sp | 实际文本仍可能受系统字体、绑定与配置影响 |
| 时间提示何时另起一行 | 比较正文与“正文＋尾部提示”的排版行数，若增加行数则在提示前主动插入换行 | 已定位一级和二级绑定路径，未逐设备实测 |
| 展开回复写什么 | 已绑定“展开更多回复”“展开 N 条回复”“共 N 条回复”的资源和内部条件 | 计数是否等于服务端总数、剩余数尚未证实 |
| 图片评论怎么定尺寸 | 默认近方形 120×120dp、竖图 120×160dp、横图 160×120dp；显式框尺寸另走限幅分支 | 多图和配置路径单列；旧 330×440px 样本只作一致性对照 |

精确条件和来源见[详情字体表](01-详情字体条件表.md)、[评论排版与文字逻辑](02-评论排版与文字逻辑.md)。机器可读资料为 [font-condition-table.json](font-condition-table.json) 和 [comment-layout-rules.json](comment-layout-rules.json)。

## 本轮核验

- 新增 81 份同版 REA Evidence，其中 60 次方法查询：57 个提供方法体、3 个未提供。另有 20 份明确标注的资源/DEX 辅助解析。
- 字体表的 111 条记录逐项对照 DEX 中的序号、字号、行高、字体类别、样式码和字重数组，全部一致；公开条件表只重点列出详情使用的 6 项。
- `styleable → 属性 id → XML 值 → Token 序号` 已连通；普通一级/二级评论的工厂资源 id、布局文件及正文 id 已连通。
- 复用 R06、R19 的原始层级计算派生几何；公开件没有用户名、评论内容、原始 UI XML 或截图。商品评价候选 `res/Vl7.xml` 已排除。
- 本轮公开件与原件摘要分别保存，详见[证据索引](evidence-index.json)。仓库整体校验入口仍是 `node tools/verify.mjs`。

## 仍然缺什么

长评论“展开全文”的完整阈值、折叠/展开状态恢复、表情与超长链接的断行、实际实验开关、部分多图配置和当前字体档位仍未取得完整证据。不能将没有找到 `maxLines` 解释成永不截断，也不能将本轮资源公式推定为全部运行路径。

接下来最值得补的是固定评论样本的长短文本、表情、横竖图对照，以及在设备上记录应用字号档位与系统字号的独立变化。动画中断、弱网和进程重建仍留在原待测表。本轮不改变旧 84 项几何、77 份机制证据、28 项参数及 100 用例的 **31 部分 / 69 待测 / 0 完整** 口径。

本轮以 Android 8.72.0 的普通一级/二级评论为对象。静态规则与旧 R06/R19 真机记录作对照，没有新增运行观察。购物评价布局 `res/Vl7.xml` 已排除；评论区笔记正文头部也没有当成评论正文。

该正文类直接继承 `android.widget.TextView`，见 [CR203](auxiliary/CR203-comment-instructions.json)，不能直接套用详情 `NoteDetailTextView` 的 Token 逻辑。[C225](evidence/C225-parent-inflate.java.txt)和 [C226](evidence/C226-sub-inflate.java.txt)还存在缓存 View 复用路径，会调用帮助器调整间距。因此下表是打包默认，不能称为每次渲染后的最终参数。

## 字号与几何

字号、继承与尺寸引用由 [CR202](auxiliary/CR202-comment-resource-values.json)解析；尾部文字的独立 Span 样式由 [CR211](auxiliary/CR211-footer-fields.json)和 [CR212](auxiliary/CR212-footer-resources.json)绑定。

| 项目 | 一级评论 | 二级回复 |
|---|---|---|
| 正文字号 | 14sp，样式 `0x7f1204b5` | 相同 |
| 作者字号 | 13sp，单行末尾省略 | 相同 |
| 作者最大宽度 | 200dp | 165dp |
| 时间 / 回复提示 Span | 12sp | 相同 |
| 赞数 | 11sp | 相同 |
| 正文附加行距 | 3dp | 3dp |
| 正文顶部 padding | 7dp | 5dp |
| 正文底部外距 | 4dp | 4dp |
| 头像 | 32×32dp | 20×20dp |
| 正文水平起点的组成 | 15dp 外侧 padding＋32dp 头像＋10dp 间隔 | 47dp 根外距＋10dp 头像外距＋20dp 头像＋5dp 间隔 |
| 合计正文起点 | 57dp | 82dp |

两类正文布局为 `match_parent × wrap_content`，未在该节点显式给出 `maxLines` 或省略方式；作者的单行截断不能误记到正文。没有发现属性不等于所有代码都不截断正文。

右侧点赞列的外前距为 10dp、动画控件宽 37dp、外后距为 6dp，中间正文容器宽度为 0dp、权重为 1。它会占用正文的横向空间，不能只按“屏宽减左右页边距”计算文本宽度。

在魅族旧样本的 440dpi 下，density=2.75；按每个 XML 尺寸分别取整，一级起点为 `41+88+28=157px`，二级为 `129+28+55+14=226px`，右侧文本边界为 `1080-(28+102+17)=933px`。这与 R06/R19 中对应节点的既有记录一致；25dp 相对缩进最终约为 69px。

派生节点矩形和原件摘要见 [comment-layout-rules.json](comment-layout-rules.json)。原 UI 层级的 id 已混淆，几何一致不能独自证明当时实际加载了这份 XML；不将它升级为新增运行覆盖。

## 时间 / 回复提示并非总是独占一行

[C233 一级绑定](evidence/C233-parent-build-text.java.txt)和 [C236 二级绑定](evidence/C236-sub-build-text.java.txt)都执行：

1. 构造评论正文，二级评论按目标关系决定是否增加“回复＋用户名＋冒号”前缀。
2. 构造尾部提示，先用尾部的纯文本与正文拼接，交给 `StaticLayout` 测量。
3. 比较“正文＋尾部”与“仅正文”的行数；若前者更大，在真正追加尾部 Span 前插入换行。
4. 设置文字、点击 Span、透明高亮和长按处理。

测量使用 TextView 的 Paint、普通对齐、行距倍数 1、附加行距 0、`includePad=false`；它是换行决策用的测量，并不表示最终控件的附加行距被改成 0。尾部实际用 12sp 的 Span，因此不能拿测量结果当最终像素截图。

[C240](evidence/C240-parent-text-width.java.txt)和 [C241](evidence/C241-sub-text-width.java.txt)还显示宽度来源有条件：`ro.m.c()` 为真时使用 `max(100, 正文控件.getWidth())`，否则取另一帮助方法；100 在这里是像素值。另一分支的最终宽度本轮未追完。

[C239 普通尾部](evidence/C239-comment-footer-format.java.txt)与 [C248 实验尾部](evidence/C248-footer-experiment-format.java.txt)都设置 `TextAppearanceSpan`，样式值是 12sp。普通路径的默认参数桥 [C247](evidence/C247-footer-default-bridge.java.txt)会将相应“附加回复”参数设为 true，另外仍有内容条件可抑制该文字。时间字符串先尝试转整数，见 [C249](evidence/C249-footer-time-format.java.txt)；具体“刚刚/几天前”的阈值未在本轮恢复。

二级绑定存在类型推断警告；本轮只采用可对照的测量、拼接和控件调用。更长评论的折叠阈值、展开全文、表情/链接断行和全部内容类型仍未知，不据这段代码宣布没有截断。

## 展开回复的文字条件

[C238](evidence/C238-replies-expand-bind.java.txt)和 [CR209](auxiliary/CR209-comment-text-resources.json)明确对应默认中文资源：

| 内部条件 | 文案 |
|---|---|
| `cVar.b() > 0` 且 `cVar.d()` 为真 | `共 N 条回复` |
| `cVar.b() > 0` 且 `cVar.d()` 为假 | `展开 N 条回复` |
| `cVar.b() <= 0` | `展开更多回复` |

资源编号为 `0x7f111cad`、`0x7f111cac`、`0x7f111cab`。N 取 `b()`；`d()` 的业务含义以及 N 是否为总数或剩余数还未证明，不能擅自解释为已经展开/尚未展开。

## 图片评论的尺寸规则

[C210](evidence/C210-comment-picture-size.java.txt)将单图或特定配置路径交给 `wg3.v.e`。进一步的 [C219](evidence/C219-picture-ratio-apply.java.txt)、[C229](evidence/C229-picture-ratio-fit.java.txt)、[C230](evidence/C230-picture-ratio-fallback.java.txt)、[C231](evidence/C231-picture-default-bridge.java.txt)和 [C242](evidence/C242-picture-dp-apply.java.txt)给出以下条件：

| 条件 | 输出尺寸，宽×高 |
|---|---|
| 图数不大于 1，`boxWidth` 与 `boxHeight` 均为正 | 两个分量分别限制在 120–160 之间，再按 dp 转换 |
| 使用原图宽高比，`0.9 ≤ width/height ≤ 1.1` | 120×120dp |
| 使用原图宽高比，小于 0.9 | 120×160dp |
| 使用原图宽高比，大于 1.1 | 160×120dp |

`boxHeight` / `boxWidth` 的字段拥有者由 [C250](evidence/C250-picture-height-field.java.txt)和 [C251](evidence/C251-picture-width-field.java.txt)确认。显式框尺寸分支是独立限幅，不是保留原图比例的等比缩放。原图宽高比确实是浮点除法，已用 [CR205 DEX](auxiliary/CR205-picture-ratio-instructions.json)排除反编译文本漏写类型转换带来的歧义。

以上宽高比表限定有效正尺寸；异常、零尺寸和 NaN 不作为已验证行为。最终应用帮助器在任一输出尺寸不为正时跳过修改。旧真机 330×440px 样本与 120×160dp 相容，但该旧样本尚未绑定到本轮精确类的执行轨迹。

[多图布局](auxiliary/CR201-layout-z4X.xml.txt)有三个图片槽，槽间距引用值为 6dp。[CR203](auxiliary/CR203-comment-instructions.json)显示普通多图方块边长在类初始化时计算为 `(wg3.f0.c() - int(dp(155))) / 3`，按整数除法处理；这不是每次窗口变化都重新计算的证明。该宽度的 Lazy 来源和只显示首图的配置运行值尚未知。

[C214](evidence/C214-comment-multi-bind.java.txt)按图片数量与配置控制槽位，[C209](evidence/C209-comment-picture-layout.java.txt)可在图数大于 3 的第三槽位或特定布尔条件下显示覆盖文字。覆盖文字的具体格式、裁切与圆角规则尚未全部取得，不补猜“+N”等文案。

本轮能提供上述有条件的实现输入；跨机型最终字号、长文本收展、实际配置和动画仍需要后续定向观察。

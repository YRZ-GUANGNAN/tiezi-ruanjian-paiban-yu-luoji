# 第十二轮：私信与聊天静态研究

更新：2026-10-15。目标是为手机端非购物功能收集私信、会话列表、聊天输入、消息附件、通知和推送跳转的实现线索。本轮只分析 8.72.0 安装包，不执行 APK，不读取或公开任何私信正文、联系人、头像原图、账号标识或原始 UI XML。

## 先给结论

1. **消息首页和单聊页是两条明确的 UI 链。** 消息首页由 `MessagePageFragment`、`MessagePagePresenter`、`MessagePageView`、`MessageRecyclerView` 和 `ChatPageMultiAdapter` 组成；单聊页由 `ChatActivity`、`ChatPageRecyclerView`、`ChatPageMultiAdapter` 和大量按消息类型拆开的 ViewHolder 组成（IM106–IM126、R12-IM-M03–M05、R12B07–R12B13）。
2. **会话和消息更新采用差分列表，而不是每次整页重建。** `ChatActivity.F0` 接收 `List + DiffUtil.DiffResult`，替换本地列表、统计新消息数量、分发差分更新，并根据首屏、加载状态和非空消息数量决定是否自动滚动或继续加载（R12B07）。这支持复刻时使用稳定消息 ID、增量插入和滚动锚点。
3. **底部操作区由数据配置驱动。** `ChatBottomConfig` 含 `id/name/type/bizType/content/link/lightIconUrl/darkIconUrl/childBottoms`；`ChatActivity.K2` 按返回列表数量创建 `GridLayoutManager`，并以 8dp 系统密度间距重建菜单适配器（IM311、R12B08）。因此输入框下方的按钮、深浅色图标和子菜单不是固定写死的单一布局。
4. **文本输入有独立的键盘/底栏状态机。** `ChatActivity.V8` 在关闭和打开输入区时分别使用 50ms、150ms 的候选过渡，切换表情图标、请求 `RichEditTextPro` 焦点并记录 `message` 入口；`onTextChanged` 监测行数变化，`afterTextChanged` 在有焦点且状态满足条件时写入编辑状态，同时把文本状态交给 presenter（R12B09、R12B05、R12B06）。这些是静态实现线索，不能当作运行时精确动画时长。
5. **消息附件是独立呈现类型。** 静态类中至少有文本、图片、视频、语音、引用、长按、表情、贴纸、个人表情、卡片、文档、发送状态和不支持类型等 ViewHolder；本轮重点证据确认文本、图片、视频、语音以及引用/长按入口（IM114–IM120、R12B14–R12B20）。
6. **语音消息包含动画和触摸状态。** `ChatVoiceViewHolder.U1` 创建并同时播放两个 `Animator`，更新时长文本并将消息状态写入 `3`；`d2` 记录触摸的 rawX/rawY，后续的拖动/取消判定仍需真机验证（R12B17、R12B18）。
7. **图片和视频包含上传进度分支。** 图片 holder 根据 `MsgUIData.X1()` 选择隐藏或显示上传进度并写入 `j3()`；视频 holder 同时处理进度和上传状态，失败/未上传时隐藏进度与相关播放控件（R12B15、R12B16）。这支持复刻“本地待上传 → 进度 → 完成/失败”的视觉状态，但不提供服务器上传协议。
8. **私信转发/分享是独立页面，并通过事件关闭。** `MsgPrivateSendController.onAttach` 装配 presenter、适配器和事件订阅；`onNotify` 收到 `multi_share_click` 或 `successCreate` 时结束页面；来源统计区分普通入口、商业转发和长按静默分享（R12-IM-M18、R12B11、R12B12）。
9. **私信数据模型覆盖用户状态、风险、置顶和动态底栏。** `MsgUserBean` 有 `isBlocked/isMuted/isTop/isFriend/isInteract/showAudio/showShareGroup/showStickyNote/showStrangerHint` 等布尔槽位，同时包含 `bottomConfig/bottomConfigV2`、`chatStickyTopInfo`、`riskPopupInfo`、`fraudInfo` 和 `chatOrderShowIcon`（IM310）。这说明会话页的可见按钮和风险提示可能随会话对象变化。
10. **消息通知与私信列表分开。** `MessageServices` 暴露系统通知、通知盒子、子页、关注、赞/收藏、提及等分页查询；`MsgNotificationV2Presenter` 把刷新状态和 RecyclerView 交给独立页面（IM128、IM124–IM126、R12-IM-M15、R12B22、R12B23）。不能把“通知”直接当成私聊消息列表。
11. **本地缓存确实有 Room DAO 结构。** `MsgDataBase`、`MessageDao_Impl`、`ChatDao_Impl` 和 `GroupChatDao_Impl` 组成消息/会话/群聊本地数据层；DAO 静态 SQL 能看到按本地会话或群会话读取、按 `store_id` 倒序分页、未读/撤回/置顶/免打扰/草稿/发送状态更新和按本地会话清理（R12-IM-B11–B15、R12-IM-D01–D12）。这比“可能有缓存”的推断更具体，但不等于已恢复数据库文件名、加密方式或线上同步协议。
12. **会话列表排序和分页有独立字段。** `ChatDao_Impl` 的查询条件包含陌生人状态、聊天状态和本地用户 ID，并以最近激活时间倒序；同时存在 LiveData/Flowable 观察和 LIMIT 分页入口（R12-IM-D06–D09）。复刻时应把 `lastActivatedAt`、`readStoreId`、`min/maxStoreId`、`unreadCount`、`draft`、`isTop`、`mute`、`blocked` 作为会话列表状态，而不是只保存最后一条文本。

## 关键页面与布局逻辑

### 消息首页

`MessagePageFragment.onCreate` 读取 `is_landing` 参数；`onCreateView` 由消息模块的布局工厂创建页面。`MessagePagePresenter.p0` 将顶部区域高度设为 0，给 `MessageRecyclerView` 设置固定尺寸、适配器和可选 `MsgBannerRVAnimation`，并配置 `SwipeRefreshLayout` 颜色（R12-IM-M03、R12-IM-M05）。这支持“消息首页是可刷新列表、顶部横幅可选”的判断；横幅是否在用户样本中出现仍未知。

`MessageRecyclerView.fling` 可记录 fling velocity，`onScrolled` 将滚动事件转给外部监听器（R12-IM-M07、R12-IM-M08）。这说明列表性能和滑动统计有独立入口，但没有公开具体阈值。

### 单聊页

`ChatActivity.onBackPressed` 在输入/底部页面状态仍存在时，优先调用 `ChatPageView.a()` 关闭当前聊天页内层状态；否则交给系统返回（R12B02）。这与“键盘/表情层先退，页面后退”的复刻验收方向一致，具体状态变量含义仍需真机操作确认。

`ChatActivity.F0` 在差分更新后维护首个和最后一个有效消息的 store ID，统计非空消息和新增数量，并根据首屏/加载状态决定滚动到新消息或触发下一页加载。它还使用 100ms 延迟任务完成后续状态同步（R12B07）。这是最有用的分页与返回锚点线索，但不能从静态代码推出服务端分页大小或网络重试策略。

### 输入区与动态底栏

`ChatActivity.K2` 按配置数量设置网格列数，使用 `ChatAverageItemDecoration`，间距候选是 8dp；更新配置时清空并重填底部菜单列表，最后调用 `notifyDataSetChanged()`（R12B08）。`ChatBottomConfig.childBottoms` 为子菜单槽位，图标同时保留浅色和深色 URL（IM311）。

`ChatActivity.V8` 在输入区开关时分别调用底栏动画和焦点请求；静态体内可见 `50L` 与 `150L` 两个候选时间值。它们是代码默认值，不能替代录像逐帧测量，也不代表所有设备刷新率下都相同（R12B09）。

`onTextChanged` 根据 `RichEditTextPro.getLineCount()` 变化触发布局更新，`afterTextChanged` 在输入框有焦点且 presenter 状态为 `1` 时写编辑状态；这说明多行输入会影响底部布局，而不是固定单行高度（R12B05、R12B06）。

## 私信模型与会话状态

`MsgUserBean` 不是单纯的联系人对象：它同时携带昵称/头像、关注状态、好友状态、屏蔽/免打扰、官方/品牌身份、机器人字段、风险弹窗、置顶信息、底部业务按钮和陌生人提示。`PrivateLetterInfo` 又提供 `isShow/name/displayText/darkDisplayText/lightIcon/darkIcon/link/actions/actionRightBtn` 等字段（IM304、IM310）。因此复刻时应把“会话对象”和“会话能力配置”分开，允许同一个消息渲染器根据对象状态决定按钮、提示和输入能力。

`ChatStickyTopInfo` 还包含 `chatId/stickyTopMsgId/storeId/senderId/operatorId/operateTime/count/enable/isStickyTop/allowShowGuide/append/effectsContents/lottieId` 等字段（IM309）。这支持“顶部置顶消息是可更新状态”的判断，但未证明客户端一定在所有会话显示置顶条。

`MsgExtra` 的 `dataSource`、`extraStr` 和 `isFromNet()`/`mergeExtraStr(JSONObject)` 表明消息额外数据可区分来源并合并 JSON（IM312）。这适合在复刻数据层保留 `extra` 扩展字段，避免把未知业务卡字段硬编码进核心消息结构。

`MessageBean` 与 `MsgUIData` 是两层消息模型：前者保留 sender/receiver、createdAt、storeId/maxStoreId、已读、撤回、引用、置顶和操作状态；后者再加入 UI 消息类型、chat/localChat ID、时间显示、未读动画、长按区域、媒体和引用 UI 数据（R12-IM-B01、R12-IM-B03）。`MsgContentBean` 与 `MsgUnreadCount` 则分别承载内容类型/正文扩展和未读计数（R12-IM-B02、R12-IM-B04）。这支持复刻时采用“传输/缓存模型 → UI 投影模型”的两段式转换。

## 通知、推送与隐私设置

安装包同时包含消息页路由、通知路由和隐私消息设置路由：`RouterMapping_message`、`RouterMapping_messages`、`RouterMapping_privacy_message_settings` 等命中于消息类搜索（IM003）。`PrivacyMessageSettingsActivity` 使用独立 linker；本轮只确认页面存在，未确认开关项目和默认值（IM127、R12B24）。

推送侧能看到魅族、华为、JPush、Getui 和本地通知服务类，以及 `RouterMapping_notification_setting`（IM010）。这些是渠道适配和通知入口的静态事实，不能直接推断收到推送后一定打开哪个页面；需要真机在测试账号和无真实私信内容的条件下记录“通知 → 应用 → 消息页/会话页”的跳转。

## 对后续复刻研究的直接建议

优先把数据和交互拆成以下状态，而不是先画一张固定聊天页：

1. 会话对象：用户信息、屏蔽/免打扰/好友/陌生人状态、置顶和风险提示。
2. 消息对象：稳定 `messageId/storeId`、发送者、消息类型、正文/媒体、发送状态、时间、引用、`extra`。
3. 列表状态：首屏、历史分页、加载中、加载失败、空态、新消息锚点、未读计数。
4. 输入状态：键盘、表情、底栏菜单、多行高度、草稿、发送中、发送失败。
5. 预览状态：图片/视频/语音/文档的加载、上传、播放、取消、失败和返回。
6. 操作权限：长按菜单随消息方向、发送者、时间窗、会话设置变化。

本地数据层再补一层：消息 DAO 需要支持按会话/群聊分页、按 `storeId` 倒序读取、发送失败或撤回状态更新、未读游标更新、置顶/草稿/免打扰更新；会话 DAO 需要支持最近激活时间排序和可观察列表。具体 SQL 只作为客户端结构参考，不能直接当作服务端接口。

真机补测只需要测试账号或空会话环境，建议按这个顺序记录：消息首页空态 → 测试会话列表 → 进入单聊 → 键盘/表情切换 → 多行文本草稿 → 图片/视频/语音附件 → 长按菜单 → 引用/转发 → 置顶/免打扰 → 返回与推送跳转。真实私信正文、联系人头像和设备账号不进入公开库。

## 未解决问题

- `ChatActivity` 中的具体网络/数据库实现被混淆和 PatchProxy 分散，当前没有可靠证据可以写出服务端接口、WCDB 表名或消息加密方式。
- 语音拖动取消、图片/视频点击预览、引用跳转、长按菜单项目和撤回时限没有本轮运行证据。
- `ChatBottomConfig` 的实际配置内容、不同会话下按钮数量、空态/风控态文案尚未取得脱敏运行样本。
- 推送渠道类很多，但通知 payload 到会话路由的运行时映射仍未知。
- 9.49.1 本轮未做同范围聊天静态对照，也没有新版真机验收。

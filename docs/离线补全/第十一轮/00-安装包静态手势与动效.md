## 新发现一：拖拽退出分页不是普通“按一下翻页”

`com.xingin.matrix.detail.item.dragexit.DragExitPagerSnapHelper` 的 `findTargetSnapPosition` 会先计算每个可见子项到末端的距离，再分别记住末端前、末端后的最近项。正向 fling 选末端后的项，反向 fling 选末端前的项；若没有候选，再按布局是否反向增加或减少一个位置。`isForwardFling` 只看水平或垂直速度的正负号，未恢复一个固定的距离阈值。

它对 `DetailFeedDragExitItemView` 有一个专门分支：当该项的“可见末端距离”恰好等于其装饰尺寸时，直接返回该项位置；随后还会在目标位置发现拖拽退出项且位置大于 0 时回退一个位置。这说明拖拽退出卡被当作分页边界节点处理，不能简单套普通 `PagerSnapHelper`。

吸附距离由 `distanceToEnd` 作为水平或垂直最终位移；`getCalculateSpeedPerPixel()` 的默认返回值为 `25.0f`。这是 `SmoothScroller` 使用的速度参数，静态结果没有给出手机上的毫秒数，也不应换算成整段转场时长。

证据：`R11-M01` `ev_6e7b3d68446e3773954aa542f0b4499514ac88249e00d5fb9b3bce2b82f944a6`、`R11-M02` `ev_0ef171c6dc858d6387ef4fc1e317cd96b902985f398466b93cba636fa39dd96c`、`R11-M04` `ev_01544adb94f063ded696db339888b087b0b7462e51ac045976cdd0975d98b024`、`R11-M05` `ev_eaf5ab3050efd7ac1c55b09151913ca7c0f94cc149f5427b7c8d98fb5d17876c`。

## 新发现二：评论面板有明确的“子列表先消费，面板后接管”条件

`BaseExtendableBottomSheetBehavior` 保存一个 `RecyclerView`、一个 `NestedScrollView` 和一个布尔开关；所以这条交接链同时支持评论列表和嵌套文本滚动。`FullScreenExtendableBottomSheetBehavior` 与 `ShortPanelBottomSheetBehavior` 都在 `onNestedPreScroll` 中检查子列表能否继续向上滚动：只要 `RecyclerView.canScrollVertically(-1)` 或 `NestedScrollView.canScrollVertically(-1)` 为真，就暂不把反向滚动交给面板。

当子内容已经到顶，面板才把 `dy` 交给父级 `BottomSheetBehavior`。向下方向还会检查面板当前状态和 `peekHeight` 对应的顶部位置；短面板额外记录本轮是否曾在初始顶部之下发生上推。两套 behavior 都在 `onStartNestedScroll` 保存初始状态，在 `onStopNestedScroll` 根据最后一次 `dy` 和顶部位置决定继续停靠或进入另一个状态。源码中的状态数字没有在本轮恢复成产品语义名称，不能把它们直接写成“展开/半展开/关闭”的固定枚举。

短面板的 `onNestedPreFling` 还有一个静态条件：初始状态为 `3`、上一次嵌套滚动 `dy > 0`、并且已记录过从初始顶部继续上推时，直接返回 `true`，截留这次 fling。这个条件解释了为什么同一次手势中列表滚动和面板位移可能出现交接，而不是所有 fling 都直接交给子列表。

## 新发现三：取消底部面板可能是“设为隐藏状态”的动画路径

`CustomBehaviorBottomSheetDialog.cancel()` 在 `setDismissWithAnimation(true)` 且 behavior 当前状态不是 `5` 时，不直接调用 `super.cancel()`，而是先执行 `behavior.setState(5)`；关闭动画和最终 Dialog 销毁之间因此存在一个状态转换边界。若关闭动画开关为假，或已经处于状态 `5`，才走普通 `super.cancel()`。

`ensureContainerAndBehavior()` 还会把自定义 behavior 绑定到容器，并设置 `hideable`。这为复刻时区分“面板位移动画”和“Dialog 生命周期结束”提供了代码依据，但没有证明所有评论面板都使用这个 Dialog 类。

证据：`AP11-022` `ev_63b242a5c0cb8390f2baccc7dd98859b0012b6512a29b37e1a6834afa2a3ec1a`、`AP11-023` `ev_5cb6297800223da1b371249c3770323bcab3a9ee927b06b2751ae86697a411b1`、`AP11-024` `ev_945173d84252c4e0d73a12a375a050b1e788416910bf62b8a928c5dbb1632dcc`。

## 新发现四：系统返回边缘手势有可配置阈值、边缘和多指路径

8.72.0 的 `com.xingin.xhstheme.view.swipeback.SwipeBackLayout` 只在 `enableGesture` 为真时拦截事件；实际事件交给内部 helper `com.xingin.xhstheme.view.swipeback.b`。helper 使用 `VelocityTracker`，处理 down/move/up/cancel、pointer down/up，并在活动 pointer 松开时尝试把同一内容 View 交给另一个 pointer 继续拖动。

捕获判断 `h(...)` 的默认分支按可拖方向选择水平、垂直或二维距离：二维时比较位移平方和，单轴时比较绝对位移与内部 `touchSlop` 字段；全屏返回模式还会按左右方向和边缘命中结果拒绝冲突方向。代码中没有恢复这个 `touchSlop` 的设备数值，因此不能从它推出“必须滑过多少 px”。

组件暴露了以下真实参数入口：`setEdgeSize(int)` 设置边缘范围；`setScrollThresHold(float)` 要求严格满足 `0 < value < 1`；`setEnableFinishEarlier(boolean)` 控制提前完成候选；`setIsSupportFullScreenBack(boolean)` 切换全屏返回并清空 pointer 边缘数组；`setEnableMotionEventCompatReplace(long)` 在传入 `0` 时开启兼容替换标记。动画推进由 `OverScroller` 的 `computeScrollOffset()` 驱动，并通过 `postInvalidateOnAnimation` 持续刷新。

证据：`R11-M24` `ev_a6f2e8126dba3c024e258db21c99f2756b013e158201c591f2d5f11e8b01d43e`、`R11-M25` `ev_e305f06675a41641c1f7717e654d1c0db7041dea0c45e9869965c3467f0dd88e`、`R11-M28` `ev_b8c5b16fe16b5ce7893d12c4591fc8f775f691a0644c06afc9222c934fb483a4`、`R11-M34` `ev_875569194c7c385d6d2e3b45c4af70b3f56d69d659ff260e765d3e7070a53120`、`R11-M35` `ev_3d88c636df40c2af13cf54898b583331b80b5b8d91c3be2ef4ef58aa81a9e5cd`、`R11-M36` `ev_dc28630afc06d44f7dc229d71b8f11a36626db7da0aa33a2212f222e878b03d1`、`R11-M44` `ev_843ed3be097c3c5d33d199807c2de66f97b6c250198af1769b6959f7e1d0780d`。

## 新发现五：9.49.1 的动画资源变化比“新增一个动效”更复杂

本地 APK 资源索引显示，按 `assets/**/*.json` 做的资源级对照为：8.72.0 记录 230 项，9.49.1 记录 1129 项；差异摘要为 158 项新增、4 项内容变化、8 项移除。这个数量包括 DSL、tracker、语言和资源 JSON，不能当作 Lottie 动画数量。

针对可解析为 Lottie 的小范围索引，8.72.0 有 93 项、9.49.1 有 146 项。可以直接用于后续真机对照的候选包括：

- 8.72.0 `explore_feed_scroll_anim.json`：19 个动画属性、50 组关键帧，关键帧时间范围 0–140；这是资源内时间轴，不是手机端耗时。
- 8.72.0 `doubleclick/double_click_like_v2.json`：10 个动画属性、27 组关键帧，时间范围 0–81；9.49.1 仍保留同名资源。
- 8.72.0 `search_result_pull_to_refresh.json`：18 个动画属性、48 组关键帧，时间范围 0–133；9.49.1 对照索引中移除该资源，是否改为 DSL、远程下发或改名未知。
- 9.49.1 新增 `avatar/avatar_start.json`、`avatar_loop.json`、`avatar_end.json`，均为 30 fps、约 72×72 画布，原始资源时间段分别为 0–29、29–62、62–96；这支持“开始/循环/结束”三段资源拆分的静态事实，但不证明某个个人页入口实际调用它们。
- 9.49.1 新增浅色/深色的 `like`、`dislike`、评论语音和生成加载资源；其中资源时间轴分别出现 30 fps、60 fps 和 100 fps，不能据此声称整套产品统一刷新率。

资源解析来源是本地 `animation-json-index.json`、`animation-focus-diff.json` 与 `lottie-metrics.json`，保留了每项路径、字节摘要和解析状态；没有公开原始资源文件。资源存在、删除或 JSON 时间轴属于静态证据，不能替代真机播放、循环次数、速度倍率和实际入口验证。

## 对后续复刻最有价值的使用顺序

1. 先把评论面板实现成“子列表滚动优先、到顶后父面板接管”的嵌套滚动状态机，再用真机录像校准状态数字对应的视觉阶段。
2. 图集拖拽退出要保留特殊退出卡节点和正负速度方向；不要只使用一个固定距离阈值，也不要把 `25.0f` 直接翻译成转场毫秒数。
3. 系统返回手势先记录边缘范围、触摸阈值和多指取消/接管，再测魅族 21 的真实数值；`setScrollThresHold` 的 0–1 合法区间可作为输入校验。
4. 对 9.49.1 先做资源入口映射和播放录屏，再决定是否替换 8.72.0 的实现参数。当前安装包 ABI 不匹配，9.49.1 仍没有真机运行结论。

## 未解决问题

- REA 方法体经过 `PatchProxy`，远程补丁或实验分支可能改变默认分支。
- 本轮没有恢复 `touchSlop`、边缘默认值、真实 `peekHeight`、动画状态数字对应的产品语义，也没有证明某个资源被哪个页面调用。
- 9.49.1 仅做资源和局部静态对照；安装包只有 `armeabi-v7a`，魅族 21 只报告 `arm64-v8a`，不能重打包伪造兼容性。
- 录屏中已观察到的 639px 返回位移、视频先收窄后放大等现象，不能仅凭本轮类名静态链确定因果，仍需真机和同版运行时交叉验证。

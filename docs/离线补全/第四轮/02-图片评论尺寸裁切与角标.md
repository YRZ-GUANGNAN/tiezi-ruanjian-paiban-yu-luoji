# 图片评论：尺寸来源、裁切、圆角与数量角标

本轮只分析 Android 8.72.0 的非购物评论。以下均为打包默认和静态请求，不代表当前账号配置或最终像素结果。条件表见 [comment-picture-rules.json](comment-picture-rules.json)，原始 Evidence ID 与摘要见[证据索引](evidence-index.json)。

## 1. 多图宽度来自 Display，并有缓存

[P317](evidence/P317-picture-width-lazy-body.java.txt)和 [P319](evidence/P319-picture-width-origin.java.txt)补齐上轮的宽度来源：

```text
WindowManager.defaultDisplay.getRealSize(Point)
    → point.x
    → wg3.f0 的宽度 Lazy
    → CommentSinglePictureView 类初始化时计算方块边长

sidePx = (W - int(dpToPx(155))) / 3    // 整数除法
```

这里的 W 是该 Display 调用返回的宽度，不是每个图片控件的当前宽度，也不是已扣除系统栏的内容宽。WindowManager 或 Display 不存在时，帮助方法返回 `[0,0]`；不因此推定后续异常布局已验证。

Lazy 绑定见 [PR301](auxiliary/PR301-picture-width-and-layout-binding.json)，边长公式复用[第三轮图片规则](../第三轮/02-评论排版与文字逻辑.md)。本轮没有证明旋转、密度变化、窗口改宽后缓存必定更新；也不能拿这条缩略图链替代详情图集的当前窗口尺寸链。

## 2. 只显示首图有两个条件

[P318](evidence/P318-picture-single-only-lazy-body.java.txt)、[P320](evidence/P320-picture-single-only-config.java.txt)、[P328](evidence/P328-picture-single-config-default.java.txt)与 [PR309](auxiliary/PR309-picture-generic-binding.json)连通：

```text
onlyFirstPicture = ro.m.c() && (配置值 > 0)
配置键 = andr_cmt_pad_multi_opt_switch
调用默认值 = 1，类型 Integer
```

设备条件和配置都有缓存，实际运行值未知。虽然键名含 `pad`，也不能写成“所有平板/折叠屏必定只显示一张”。设备分类逻辑继续沿用[适配追踪](../02-设备适配静态追踪.md)。

第三轮 [C214](../第三轮/evidence/C214-comment-multi-bind.java.txt)显示：从选定的本地或远端图片列表取得总长度，将总数写入各图片的临时信息；只首图条件为真时隐藏后续槽位。**隐藏槽位不等于把总数改为 1。**

## 3. “共 N 张”是总数，不是剩余数

[P311](evidence/P311-picture-overlay-text.java.txt)、[PR305](auxiliary/PR305-picture-resource-field-binding.json)、[PR306](auxiliary/PR306-picture-style-resources.json)明确绑定了数量角标的资源：默认中文 `共%d张`、英文 `%d images`，N 不减去可见图片数。XML 的 `共9张` 只是初始化文字，不是 9 张上限。

出现条件由原 [C209](../第三轮/evidence/C209-comment-picture-layout.java.txt)和 PR301 的原始指令核对：

- 普通多图：总图数大于 3，且当前为第 3 格（索引 2）。
- 只首图路径：只首图条件成立，且总图数大于 1。

| 数量角标的打包默认 | 值 |
|---|---|
| 位置与外距 | 默认中文从左到右布局下位于右下；逻辑末端（`marginEnd`）与下外距各 6dp，不能将末端一概写成物理右侧 |
| 字号 / 颜色 | 10sp / 白色 |
| 内距 | 左右 4dp，上下 1dp |
| 最小高度 | 16dp，不是固定高度 |
| 背景 | `#80303034`，圆角半径 16dp |
| 初始可见性 | `gone`，由绑定分支控制显示 |

布局由 `mp5.i.z → 0x7f0c14de → res/GWn.xml / res/6jm.xml(-v22)` 绑定，见 [PR302](auxiliary/PR302-picture-layout-resource.json)、[PR303](auxiliary/PR303-picture-layout-attributes.json)。背景形状和颜色由 [PR313](auxiliary/PR313-picture-badge-background-attributes.json)核对。这是数量角标，不是中央加载进度或 LivePhoto 标识。

## 4. 图片默认 6dp 圆角，居中裁切

这里没有仅凭常见库的数值枚举猜测语义，已经把资源 id、索引、解析方法和返回对象接起来：

| 属性 | 绑定证据 | 本轮可用结论 |
|---|---|---|
| `0x7f04008e=6` | `z6.a.a[0]` / `z6.a.b=0` → `j7.c.c` 的 case 6 → `i7.q$c.i` → `i7.q$e`，对象标识 `center_crop` | 所选布局的缩放默认是居中裁切 |
| `0x7f0405cb=@0x7f0702e6` | `z6.a.a[24]` / `z6.a.z=24` → `getDimensionPixelSize` → 默认四角传入相同半径 → 8 项 x/y 半径数组 | 所选布局图片圆角默认为 6dp 转换后的像素 |

解析器来源：[P329](evidence/P329-picture-hierarchy-attributes.java.txt)、[P330](evidence/P330-picture-scale-enum.java.txt)、[PR311](auxiliary/PR311-picture-hierarchy-parser.json)、[PR312](auxiliary/PR312-picture-radius-and-scale-binding.json)、[PR315](auxiliary/PR315-picture-scale-identity-confirmed.json)。构造/解析调用链由 [PR307](auxiliary/PR307-picture-render-and-config.json)、PR309、[PR310](auxiliary/PR310-picture-hierarchy-link.json)及 [P332](evidence/P332-picture-hierarchy-inflate.java.txt)连接。复杂解析分支有反编译告警，关键映射和分支已与原始指令对照。

[P321 在线加载](evidence/P321-picture-online-render.java.txt)与 [P322 本地加载](evidence/P322-picture-local-render.java.txt)还分别经默认参数 mask=72 请求 `CENTER_CROP`；PR307/PR309 对照了原始默认参数桥。**按图片比例选择外框，不等于框内图片完整显示、绝不裁切。**

仍须区分：图片默认半径 **6dp**，角标背景半径 **16dp**。主题、四角开关、热补丁及加载后的覆盖未运行核验；这里不能直接换算成所有机型最终截图上的固定像素值。

## 5. 旧单图布局与新多图槽位并存

[P316](evidence/P316-picture-legacy-ctor.java.txt)、PR301 和 PR303 确认 `CommentPictureItemView` 与 `CommentSinglePictureView` 不是同一个控件路径。旧布局 `res/6nv.xml`、`res/RV3.xml` 的内部图片初始为 120dp 正方形；新单图内部 XML 初始为 71dp 正方形，后续数据绑定会按单图/多图规则调整。

因此不能把 71dp、120dp、120×160dp 和多图公式合并成一个“图片评论固定尺寸”。当前页面实际选用旧路由还是新路由，仍需运行证据。单图宽高比、显式 box 尺寸限幅仍复用第三轮结论，不重复计为新增测量。

最值得补的实测是：1/2/3/4+ 张图片的固定样本、横竖图裁切、图片与角标两种圆角，以及动态改宽→重新进入→重启的差异。见[定向补测表](03-定向补测表.md)。

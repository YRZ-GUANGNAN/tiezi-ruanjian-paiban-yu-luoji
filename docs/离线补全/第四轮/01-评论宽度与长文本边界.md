# 评论宽度与长文本：已确认什么，不能套用什么

对象为 Android 8.72.0 的普通一级评论与二级回复。本轮为静态分析，没有操作手机或模拟器。条件表见 [comment-text-rules.json](comment-text-rules.json)，完整 Evidence ID、原件和公开件摘要见[证据索引](evidence-index.json)。

## 1. 尾部换行的测量宽度补齐了

第三轮已经确认：追加时间/回复提示前，会比较两次 `StaticLayout` 的行数。这次补齐了它使用的宽度来源。

| 条件 | 一级评论 | 二级回复 | 计算时机 |
|---|---|---|---|
| `ro.m.c()` 为真 | `max(100, 正文控件.getWidth())` | 相同 | 调用时读取控件宽度 |
| `ro.m.c()` 为假 | `W - int(dp(110.5))` | `W - int(dp(135.5))` | Presenter 实例的 Lazy 首次取值后缓存 |

第二行先计算候选值；**只有候选值不大于 0 时才替换为 100px**。这与第一行的“至少 100px”不是同一个规则：例如候选值为 17px，第二行仍返回 17px。

- `W` 来自当前 View 的 Context 的 `Resources.displayMetrics.widthPixels`；复用第二轮 [W104](../第二轮/evidence/W104-q68-o1-h.java.txt)。
- 固定留白的 dp 转换使用 `Resources.getSystem().getDisplayMetrics()`，随后 `float-to-int`；不能直接写成最终 XML 边距之和。
- 一级 Lazy 使用 `LazyThreadSafetyMode.NONE`，二级使用无 mode 参数的 Lazy 工厂；这是缓存初始化差别，不是刷新动画策略。
- `ro.m.c()` 的设备/配置条件沿用[此前适配追踪](../02-设备适配静态追踪.md)，不把它简写成“平板必定开启”。运行值未采到。

新来源：[L308](evidence/L308-parent-text-fallback-width.java.txt)、[L309](evidence/L309-sub-text-fallback-width.java.txt)、[L329](evidence/L329-parent-width-formula.java.txt)、[L330](evidence/L330-sub-width-formula.java.txt)。[LR303](auxiliary/LR303-binder-init.json)核对构造时的 Lazy 绑定，[LR304](auxiliary/LR304-width-lambda-instructions.json)核对原始浮点常量、截断和分支。REA 没有提供两个构造方法体，保留 [L314](evidence/L314-parent-init.json) / [L315](evidence/L315-sub-init.json) 的限制，不把辅助 DEX 冒称 REA 方法体。

这是**尾部换行判断使用的测量宽度**，不是给 TextView 设置宽度。以 `W=1080px、systemDensity=2.75` 代入得到 777/708px；第三轮旧节点几何宽度是 776/707px。这些是不同来源的量，1px 差异保留，不据公式修改旧测量，也不称为新真机观察。

对后续独立实现最有用的提醒：当前控件宽度、资源宽度和缓存时机必须分别记录。窗口变化后旧 Presenter 是否仍在使用、何时重建，尚未通过本轮运行测试证明。

## 2. 富文本切片不等于“超过 N 字折叠”

已定位的生产与绑定节点如下，中间全部状态传递尚未穷尽：

- 一级：`ah6.d.n2 → ah6.h.l0` 生成富文本；`ah6.d.q.a → ah6.h.L` 交给正文绑定。
- 二级：`ch6.d.d2 → ch6.h.j0` 生成富文本；`ch6.d.q.a → ch6.h.L` 交给正文绑定。
- 共用解析入口：`sq5.a1.s → sr7.g.s → sr7.g.t`。

来源：[L331](evidence/L331-parent-text-flow.java.txt)、[L332](evidence/L332-sub-text-flow.java.txt)、[L333](evidence/L333-parent-text-callback.java.txt)、[L334](evidence/L334-sub-text-callback.java.txt)与[直接引用扫描 LR306](auxiliary/LR306-comment-text-callbacks.json)。正文及尾部绑定复用[第三轮报告](../第三轮/02-评论排版与文字逻辑.md)。

[L326](evidence/L326-rich-parser-delegate.java.txt)中的 `substring` 用来分离命中的富文本片段：追加前段、转换片段、继续处理后段，最后追加剩余文字。没有在这段方法中得到固定字数或行数的折叠阈值。[L335](evidence/L335-rich-parser-normalize.java.txt)还有预处理，因此也不能把它说成原文逐字不变。表情、链接等插件及中间状态未全部追完。

## 3. 三种相似线索必须隔离

| 找到的线索 | 实际证据 | 为什么不能直接写成普通评论规则 |
|---|---|---|
| `... 展开全文`、`展开全文` 两个打包资源 | 指令引用指向 `VideoNoteContentView.D` | 属于视频笔记内容的排版路径，不是本轮一级/二级评论控件 |
| `comment_fold`、`all_alpha_comment_fold` 配置键 | 直接消费者为 Alpha 聊天/游戏评论适配器及配置包装方法 | 同名“评论”不代表普通笔记评论；具体折叠语义也未在本轮展开研究 |
| `th6.i.h` 的切换状态 | 展示译文/查看原文、翻译中及缓存译文处理 | 翻译状态不能当成长评论的展开状态 |

资源与引用见 [LR301](auxiliary/LR301-expand-literal-clues.json)、[LR302](auxiliary/LR302-text-and-expand-references.json)、[L328](evidence/L328-video-note-content-expand.json)。配置读法见 [L321](evidence/L321-fold-literal-consumer.java.txt)、[L322](evidence/L322-fold-alpha-consumer.java.txt)，消费者见 [LR305](auxiliary/LR305-fold-config-references.json)。翻译入口见 [L311](evidence/L311-comment-translation-change.java.txt)。L328 含大量反编译重复块警告，本轮仅用可与 DEX 对照的资源归属，不从中发布完整正文折叠算法。

## 4. 长评论仍然不能给出阈值或恢复承诺

**结论是“本轮未建立普通评论的折叠阈值”，不是“普通评论永不折叠”。** 字数阈值、行数阈值和展开状态恢复均保留未知，不填入 3 行、6 行或其他经验数字。

搜索边界已记录：资源/字面量扫描涉及 66,202 个资源项、249,475 个 DEX 类、1,368,988 个方法；正文操作引用扫描只覆盖 LR302 列出的前缀，共 1,938 个方法。资源引用则搜索全 DEX 指令。上述数字是静态扫描范围，**不是覆盖了全部功能**，也不包含远端文案、反射、热补丁、native 或所有继承路径。

下一步需要已存在的固定长评论样本，验证折叠是否出现，再测翻译、回复展开、列表复用和返回后的状态。没有样本就保留“样本不足”，不要为测试发布评论。具体见[定向补测表](03-定向补测表.md)。

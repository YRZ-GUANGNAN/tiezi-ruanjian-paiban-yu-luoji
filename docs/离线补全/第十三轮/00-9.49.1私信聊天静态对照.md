## 2. 结论摘要

1. 9.49.1 仍保留主聊天链：`ChatActivity`、`MessagePageFragment`、`MessagePageView` 和 `MsgPrivateSendActivity` 均可在 APK 类级索引中定位。这里证明的是类结构存在，不是页面一定会在当前账号或当前入口出现。
2. 9.49.1 出现一条更清晰的 Hedwig 会话持久化链：`HedwigDatabase`、`ConversationDao_Impl`、`MsgUnreadService`。它与第十二轮 8.72.0 记录的 `MsgDataBase`/旧 Room DAO 形成版本对照，但本轮没有证明旧链已删除或完全迁移。
3. 会话 DAO 的有效方法体显示：按 `user_id` 分页查询，按 `intimacy_score DESC` 排序；批量插入包在 Room 事务内；按 `conversation_id IN (...)` 查询后仍按亲密度降序。这是静态 SQL 事实，不等于当前账号的列表顺序必然如此。
4. 消息中心和通知链更细：评论更新接口为 `/api/sns/v3/message/you/mentions/specific`；通知曝光上报接口为 `/api/sns/v2/message/event/exposure/report`，字段包括 `user_id`、`message_id`、`sender_id`、`type`。接口声明不证明请求已发出或服务端一定接受。
5. 未读链包含 `chat_target_id`、`chat_type`、`read_store_id`、`unread_count` 四个请求字段；全局未读计数方法在本轮只有接口签名。搜索链存在“全量搜索”和“单条搜索”两个方法，单条搜索静态路径为 `/api/sns/v6/message/search/one`，参数为 `keyword`、`num`、`id`。
6. `MsgCenterMuteUpdater.updateModel` 的有效重载在 `PatchProxy` 未接管时把 `MsgCenterDataBean.muteInfo` 的布尔值设为 `false`。这只说明该数据流的一个静态分支，不等于用户点击“免打扰”后永远关闭。
7. 新类名还暴露出 DSL 消息卡、消息气泡、聊天风险提示、语音转文字信息和宠物聊天等结构。它们可作为后续 UI/交互采集的候选，不应直接写成已验证功能。

### 3.2 会话存储与排序

`HedwigDatabase` 暴露 `ConversationDao`，`ConversationDao_Impl` 的方法级结果提供了以下 SQL 事实：

- `a(user_id, limit, offset)`：查询 `hedwig_conversations`，按 `intimacy_score DESC` 排序并使用 `LIMIT`/`OFFSET`；读取字段包括 `conversation_id`、最近发送/打开/接收时间、置顶、会话类型、亲密度、拉黑、免打扰、创建和更新时间。
- `b(List<Conversation>)`：批量插入前开启 Room 事务，成功后提交，异常时结束事务。
- `e(user_id, conversation_ids)`：动态生成 `IN (...)` 占位符，按给定会话 ID 过滤，结果仍按 `intimacy_score DESC` 排序。

对应证据：`HedwigDatabase` `ev_3219131e31a76ab8d1b06d3f4d2acc255a0e4ede361fcfbfd2eb3e0ca44d7ecd`；`ConversationDao_Impl` `ev_896c39a4cd5ded9cb08486e762abf192be2b3d8f89c78f58b16a5c9cecfbc15b`；方法证据见 `ev_a25a17415f90b276661714a594b7e2210043be422b48fa0d43aad5502cb5cbd0`、`ev_cf05ad581facfb43bdf08615a9b103310d4cddd3ab62698c3e98b05c24246278`、`ev_5252845803520c201a36ba83451c37a7a7aecd661a75a552b81e9194c422dddd`。

## 5. 宠物聊天输入分支（静态）

`PetChatActivity.ta(View, MsgUIData, int)` 的有效方法体显示了一个消息项处理分支：

1. 根据 `MsgUIData.Y1()` 把消息状态写成 `11000` 或 `-1`，随后通知列表项刷新。
2. 读取消息扩展里的 `file_path`；没有路径时走文本/普通输入回调。
3. 有路径时从本地消息扩展读取 `duration`，解析为长整型，再交给 `PetChatInputBoxViewModel`。

对应方法 Evidence：`ev_7dd8ae996ffe9ae081b305e87a3e53ff1a417c626e50ad5ad6ac0f6cdb6b4514`。这是静态控制流和字段读取，不代表当前版本一定能在未登录状态打开宠物聊天，也不代表状态码含义已被官方定义。

## 7. 后续最有价值的手机测试

等设备再次可用时，建议按低风险测试账号逐项采集，不读取或公开真实私信内容：

1. 消息首页：冷启动、返回、下拉/上拉、置顶和免打扰的终态层级与几何；记录是否出现 Hedwig 结构对应的排序变化。
2. 未读：用两个自有测试账号发送一条文本，分别记录消息角标、进入会话、返回列表和 `read_store_id` 变化；只记录状态与时间，不记录正文。
3. 搜索：输入自造关键词，确认全量搜索、单条搜索的入口、空结果、分页和返回动画。
4. 消息形态：自造文本、图片、短视频、语音和引用消息，记录气泡尺寸、语音转文字入口、长按菜单和失败重试，不上传联系人或真实内容。
5. 宠物聊天/风险提示/DSL 卡：只验证入口是否可达、空态和错误态；若入口受灰度或账号限制，记录为未知。
6. 新旧版本：同一测试账号、同一屏幕尺寸、同一字体/密度条件下，对比 8.72.0 与 9.49.1；把版本差异与随机推荐、服务端灰度分开。

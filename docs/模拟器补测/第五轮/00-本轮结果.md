# 第五轮：长评论收展与图片呈现的模拟器实测

本轮已把第四轮的部分静态线索补成运行证据：找到两条真实折叠的长评论，验证展开、主动收起及部分返回状态；对照同一评论的动态改宽；取得横图、竖图缩略图与大图配对。没有找到可确认的 2/3/4+ 图评论，窄屏重新进入详情的完整对照也未完成。

环境为 MuMu Android 15、应用 **8.72.0 / 8720916**。默认 1080×1920、280dpi、系统字号 1.0；本轮只将宽度改为 720 再恢复，未改密度和字号。界面外观为深色；应用内字号档位未读取。模拟设备报告的品牌不能作为真实手机品牌证据。本轮没有升级、重装、清数据或杀进程。

## 可以采用的结论

| 研究问题 | 本轮结果 | 边界 |
|---|---|---|
| 长评论是否折叠 | 两个样本在原宽度下均显示 4 行折叠正文，末尾有“展开” | 不是全局四行阈值；字数、字形与富文本条件仍未知 |
| 展开、收起如何改变布局 | L1 正文 4→6 行；L2 4→5→4 行，L2 收起后层级摘要恢复相同 | 文字节点高度包含正文、收展控件与时间/地区/回复，不能称为纯正文高度 |
| 状态保留到哪里 | L1 滚出可视区再返回、进图片查看页再返回后保持展开；关闭评论面板再开后恢复折叠 | 不证明控件实际回收；不是进程重启测试 |
| 改宽如何影响文字 | L1 展开节点宽 886→526px、正文 6→10 行；同一进程、密度与系统字号不变 | 不证明内部测量缓存或远端配置已刷新 |
| 折叠与重新换行是否同一件事 | 720 宽重开评论面板后折叠正文为 7 行，节点文字与原 1080 宽折叠状态逐字相等 | 不能直接解释成统一行数限制，也不能直接认定缓存根因 |
| 单槽图片如何显示 | 横图 280×210px，竖图 210×280px；打开大图后返回可恢复本次列表位置 | 只确认一个可见槽，未读取源图数组长度 |
| 横图是否裁切 | 一对截图的拟合支持近似居中裁切；可见圆角约 10px | 属于单样本像素估计，不能替代源图坐标和真实渲染路径 |
| 2/3/4+ 图及角标 | 样本不足 | 不用缩略图内的拼图格数冒充评论图片数量 |

## 本轮计数与恢复

本地采集 **E037–E088 共 52 次**，公开选入 **35 条脱敏摘要**，另 17 次个人页、导航、视口裁切或过渡步骤只保留本地。完整性检查覆盖 207 个本地原件，包括截图、UI 层级、观察记录和动作记录；另保存 4 份 REA 环境 Evidence。没有新增录屏或安装包静态分析。

E037 初始为个人页，不导出其账号或几何。E050 首次图片引导遮挡，不用于精确裁切；之后用 E077 补了无引导观察。E060/E061/E063 未观察到评论面板，作为异常记录，不计成功对照。E087 的目录名字虽然包含 home，实际仍在搜索入口；**E088 才是核实过的最终首页**。

结束时显示为 **1080×1920、280dpi、系统字号 1.0**，无显示尺寸覆盖，处于首页。所有有 PID 的本轮观察为同一进程。未点赞、收藏、关注、发布、发送评论/私信或交易；仅浏览已有内容与可恢复显示调整。原始图片、原始 UI XML、正文、账号和设备标识留在本地，公开文件只含脱敏状态、尺寸、摘要和限制。

旧 **84 项排版指标、77 份机制证据、28 项参数**和原 **31 部分 / 69 待测 / 0 完整**用例统计保持不变。本轮结果是指定版本、单模拟器、有限样本的新增研究，不代表整个小红书或跨机型适配已经完成。

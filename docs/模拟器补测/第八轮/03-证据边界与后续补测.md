# 证据边界与下一步

这轮只补了同版本模拟器上的有限交互路径。可见终态稳定不等于内部状态完全恢复，也不等于真机操作体验已通过。

## 能复核什么

- 38次采集、198份观察原件的SHA-256；公开选35条，3条导航只保留摘要与排除说明。
- 20段615帧完整解码；ffprobe独立计数、逐帧PTS严格递增与原录像摘要核对。
- 返回位移、整卡/共同可见区域像素对齐；候选模板误差和是否接受分别保留。
- 六个连续操作序列的前后PNG与完整XML相同。主研究者还独立复算了这些终态对照。
- 环境REA Evidence只公开白名单投影；Evidence ID对应本地完整原件，不把投影当作全部Evidence。

公开索引见[evidence-index.json](evidence-index.json)。公开库校验只检查派生资料与摘要关系，不能在缺少原始录像或APK时重新运行设备实验。

## 不能从这些数据推出什么

1. **指令间隔不是手指间隔。** 两次swipe之间已释放触点；主机记录的指令起止没有与设备触摸事件、录像PTS精确对时。零额外等待也不等于设备端零间隔。
2. **稀疏录屏不是屏幕每一帧。** 请求7秒、容器时长、标称帧率和采样间隔都不是动画时长、刷新率或卡顿证据。
3. **相同参数不保证相同中断阶段。** 两次零等待面板序列的中间画面不同，不把其中一次写成固定时间表。
4. **暗像素不等于视频边界。** 本轮暂停画面有较暗内容；单行“非黑像素宽度”可能小于媒体宽度，带状区域外包络也只是像素证据，不当容器尺寸或统一缩放比例。
5. **结果相同不等于原因相同。** 639px位移在四条路径出现，停留时间和执行顺序未匹配，不能确定触发条件。它不是值得照搬的排版规则。
6. **观察数不等于完整用例数。** 原31部分/69待测/0完整不变，没有增加完整覆盖。

E202曾录到另一视频不可用的画面，稍后的层级已处于自动下一条；E203确认当前内容，E204返回。截图和XML不是同一瞬间的原子采集，因此这些导航记录没有混入7评论视频的面板对照，也没有生成“不可用倒计时的精确时长”结论。

## 接下来最值得做

| 优先级 | 补测 | 要回答的问题 |
|---|---|---|
| 1 | 真机单次持续触摸的反向、松手后再反向，分别重复 | 模拟器释放式双手势的结论能否迁移到真实跟手体验 |
| 1 | 同一低位卡片、相同停留时长、交替执行直接返回与单项操作 | 返回位移是否稳定依赖某项操作、时间或后台变化 |
| 2 | 转场不同阶段中断、反复开关及旋转/前后台 | 是否出现错误返回层级、残留遮罩、错误媒体位置 |
| 2 | 独立图片查看器与上一轮多图异常的生命周期对照 | 查看器的缩放/进退和进程重建是否改变异常 |

真机触觉、响应延迟、高刷新率、精确多指、弱网和进程恢复仍未验证。应用内字号档位未读取，9.49.1也没有新增运行验证。没有为了补测试而发内容、互动或交易。

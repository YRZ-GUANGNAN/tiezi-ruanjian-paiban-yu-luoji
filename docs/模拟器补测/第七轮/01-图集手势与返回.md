# 图集手势、边界反馈与返回位置

对象是首页进入的一条两图图文笔记，记作G1。原图与正文不公开。页序由UI描述与截图的两幅不同图、指示点对照；输入时长是单指注入的请求参数，不等于真实手指速度。

## 少量位移也可能翻页

| 证据 | 起态 | 输入 | 终态 |
|---|---|---|---|
| E142 | 第1张 | 向左60px / 600ms | 第2张 |
| E143 | 第2张、末页 | 向左620px / 350ms | 第2张，边界反馈后恢复 |
| E146 | 第2张 | 向右12px / 180ms | 第2张，仅2帧，过程未知 |
| E147 | 第2张 | 向右60px / 180ms | 第1张 |
| E148 | 第1张 | 向右500px / 350ms | 第1张，边界反馈后恢复 |

图片终态报告范围均为 `[0,140,1080,1580]`。60px约为屏宽5.6%，但两个方向的请求时间不同且各一次，不能得出精确距离阈值、速度阈值或“超过多少必翻”。E143目录名包含`gallery-next`，实际起态已经是第2张；以证据结果为准。

E144尝试12px/600ms时触发长按菜单，主采集端随后用E145系统返回关闭，未分享。这说明慢小位移不能自动视为普通短拖。菜单中有联系人，全部画面、UI和录像排除公开与独立图集复核。没有继续测试长按菜单的外部动作。

## 边界不是整张图统一平移

5段手势录像共180帧全部解码。对同一高度y800、源x=64/420/820的局部模板进行配准，约4px量化：

| 样本帧 | 三处局部横移 |
|---|---|
| E143帧20 | −24 / −20 / −8px |
| E148帧17 | +4 / +12 / +20px |

同一帧不同横向位置并非相同位移，之后回到原页，支持“局部形变再恢复”的描述。不能据此指定某个系统组件、边缘拉伸公式或弹簧参数。匹配误差、视频压缩和4px量化都保留在[数字结果](video-analysis.json)。

E142、E147能看到先小幅移动、再完成切页；未同步真实松手时刻，不将录像片段长度写成松手动画时长。上、下操作栏在这些录像中相对稳定，不能扩大为逐像素完全不变。

E149单击主图后仍在详情，3个采样帧也未显示独立查看器。只能记录本次尝试的结果，不宣称所有主图都不能打开查看器，也没有做可能触发点赞的双击。

## 返回位置：一次位移与一次反例

E140进入前，同一卡片边界为 `[544,950,1072,1810]`；经过图集手势、主图单击尝试、输入层和正文滚动后，E154系统返回时变为 `[544,311,1072,1171]`。

- 卡片均528×860px，整体上移639px。
- 按各自边界取整卡对齐，像素平均绝对误差0、完全相同比例100%；不只是类似封面。
- E155从当前位置重进，未滚动详情，E156立即返回：卡片仍为后一个位置，整卡像素和E154完全相同，完整UI层级摘要也相同。

因此，“每次返回固定上移639px”不成立；首次位移的原因还没有隔离。不能照搬为导航规则，也不能只凭这组记录归因缓存或详情滚动。后续需把图集手势、输入层、正文滚动拆成独立对照。

## 后续验收关注点

后续独立产品应分别验证翻页成功/未成功的终态、首尾不循环时的反馈、内容与固定栏的运动范围，以及详情返回后的卡片锚点。这里列的是待验收条件，不是在本对话生成实现或选择技术栈。

- E102 第31帧（PTS 0.963189秒）至第32帧（0.979433秒），标志图像从y=1338移至1461。
- E103 第34帧（PTS 0.946622秒）至第35帧（0.963000秒），从y=1461回到1338。
- 全片的匹配采样只出现这两个位置。相邻间隔16.244/16.378毫秒只是采样界限，不能当作展开/收起动画时长，也不能排除录屏未采到的更短中间显示帧。
- 可见短暂按下背景，不能把颜色变化当成高度插值动画。L1节点高度变化也是123px，与标志位移相容，但像素模板不是控件边界。
- E109 初始标题位置匹配截至第33帧/0.946378秒，之后不再匹配；不能把匹配消失时刻当作退出动画结束。

原始录屏、接触表、完整截图和 UI XML 都只留本地。本轮没有把桌面输入时钟与录像 PTS 做精确同步，也没有复用旧白色主题/2340高录像的坐标来测本轮深色1920高画面。

## 下一步按价值排序

1. **M1 多图的生命周期对照。** 保留当前样本定位，单独设计同版本应用级重启前后测试，不清数据、不升级。先核实549px大槽问题在新进程是否仍存在；没有新结果前，不归因于缓存，也不把异常宽度加入通用参数。
2. **L3 展开初始状态的原因。** 从普通评论真实绑定链追作者、置顶、带图与展开状态字段；或增加只差一个条件的现有样本。当前只证明这条评论关面板重开后恢复展开。
3. **2/3/4张与角标。** 用真实可见总数固定样本，在正常布局下量槽位、间距和角标。不能靠单张拼图、裁切节点或8张样本代替全部组合。
4. **手机与新版复核。** 优先魅族原8.72.0，再单列9.49.1。模拟器不能替代OEM字体、触摸中断和不同机型适配。

第五轮窄屏失败维持“历史异常、本轮两次未复现”；本轮多图几何维持“异常、原因未知”。没有完整覆盖弱网、进程恢复、发布、消息、直播或服务端逻辑。原100项用例仍为 **31部分 / 69待测 / 0完整**。

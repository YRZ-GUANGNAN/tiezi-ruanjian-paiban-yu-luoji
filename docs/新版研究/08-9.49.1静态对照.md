# 9.49.1 静态对照：我的页面、设置与背景图编辑

更新：2026-10-15。本页把应用宝 **9.49.1** 与魅族 21 / 模拟器研究基线 **8.72.0** 的相关 Android 静态证据整理成可追溯摘要，服务于手机端非购物功能的后续复刻研究。

这不是新版真机验收，也不是完整 APK 反编译报告。9.49.1 只做离线静态分析；8.72.0 的页面进入、返回、权限空态和节点几何来自第九轮模拟器观察。所有结论都区分“静态看见”和“运行时未知”。公开索引见[脱敏静态证据索引](08-9.49.1静态对照.json)。

## 先给结论

1. `ProfileBannerImagePreviewActivityV2` 和 `FileChoosingParamsV2` 在 8.72.0 已经存在。因此不能把它们写成 9.49.1 新增功能（8.72.0：O001/O002/O003/O004；9.49.1：N308/N311/N341/N343/N344）。
2. 9.49.1 仍保留旧背景预览链：`ProfileBannerImagePreviewActivity`、`ProfileBannerImagePreviewFragment` 和 `ProfileUploader` 均可静态定位（N301–N303、N342）。8.72.0 的现场两个入口也实际进入旧 `ProfileBannerImagePreviewActivity`（E216/E234）；V2 只是静态候选，不能替代现场入口。
3. 9.49.1 的 V2 `createLinker` 反编译结果比 8.72.0 展开更多：从一行式 `new d(...).a(viewGroup)` 变成显式创建 `ProfileBannerImagePreviewView`、依赖对象、事件对象和 linker/controller（O004 对 N344）。这是可见的实现结构差异，不足以单独证明页面架构或运行体验已经改变。
4. 选图参数的字段结构没有被静态证据推翻：两版 `FileChoosingParams.Image` 都有 `maxCount`、`maxWidth`、`maxHeight`、`quality`、`clipShape`；两版 `FileChoosingParamsV2` 都有 `maxSelectCnt`（PB039/PB041 对 N337–N340；O003 对 N311/N336）。这只能说明配置槽位，不能说明本次选图数量、输出像素或裁剪框。
5. 旧预览页仍把编辑结果写回跨平台 `banner_image` 数据并保留上传回调结构（N320/N323；同版已有 PB028/PB030/PB033/PB043）。服务器字段、上传成功、保存后刷新和新版实际执行路径仍未确认。

## 已确认的静态变化

### 1. V2 预览页的 linker 组装更展开

8.72.0 的 `ProfileBannerImagePreviewActivityV2.createLinker` 主要是：取出 `banner_preview_bean`，构造 `d`/`a`，再调用 `.a(viewGroup)`（O004）。

9.49.1 的同名方法可见以下步骤（N344）：

- 从 Intent 读取 `banner_preview_bean`，记录 `userId` 与 `allowEdit`；
- 对空 bean 记录错误；
- 创建 `ProfileBannerImagePreviewView`；
- 创建依赖对象和事件对象；
- 组装回调/依赖并返回新的 linker。

这支持“新版反编译可见的依赖装配变多”这一有限结论。它不支持以下更强的说法：新版一定使用了不同页面、动画一定改变、现场入口一定切到 V2，或内部模块边界已经完全重写。混淆、生成代码、PatchProxy 和反编译展开方式都可能造成表面差异。

### 2. 编辑资料页的 linker 也从简化构造变成显式组装

9.49.1 的 `EditProfileNewActivity.createLinker` 显式创建 `EditNewProfileView`、依赖、多个回调/子对象，并携带 `isBrandAccount` 分支（N346）。8.72.0 同类静态证据 PB007 已确认有 `createLinker`，但本页不把两个反编译体的行数差异当作用户可见变化。

### 3. 参数类型命名出现差异，但语义未确认

`FileChoosingParamsV2.materialType` 在 8.72.0 的显示类型为 `f49.a`，9.49.1 显示为 `qpd.a`（O003 对 N311）。这是静态类型/混淆命名差异；不能直接解释成素材类型规则改变。`maxSelectCnt`、相机入口和 `useGetContentActionFlag` 等字段仍在两版类摘要中出现。

## 背景图入口与页面体验：当前证据边界

8.72.0 的运行资料已经确认：我的页直接点头图、编辑资料的背景图行都进入同一个旧背景预览页；更换背景后的现场采集因系统权限页中断，随后看到相册权限空态，未授权、未选图、未裁剪、未上传或保存。背景预览图节点在该样本为 `[0,528,1080,1392]`，但这是现场显示区域，不是静态裁剪输出尺寸。详情见[第九轮背景图入口与静态裁剪](../模拟器补测/第九轮/03-背景图入口与静态裁剪.md)。

9.49.1 的静态代码补充了：旧 Fragment 仍读取 `edit_profile_changed_data_*`，把 `banner_image` 的 `value` 和 `file_id` 写回跨平台数据，并发出 `ProfileEditUpdateKey`（N320）；旧 Activity 仍创建 Fragment、关闭侧滑返回并设置进入转场（N347）；选图参数仍存在 `maxCount` 等字段（N337–N340）。这些都不能替代新版真机的权限、裁剪手感、上传进度或保存刷新测试。

## 误读排除

- `N340` 文件名是“max-width”，但对应方法体 `b()` 返回的是 `maxCount`；本页按方法体和字段名解释，不把它当作 `maxWidth` getter。
- `N323` 的 `ProfileUploader.a` 是新版静态查询中的方法；`O005` 是旧版同名 `a` 的另一种实例方法签名。两者不能只凭混淆方法名相同就宣布上传 API 已重写。
- `N341`/`N342` 是静态 incoming-reference 结果。它们只能说明当前 JADX 查询边界内的关系；反射、动态路由、运行时配置和未解析调用仍是未知。
- `N345`、`N347` 等旧链证据不能证明 9.49.1 的实际现场页面。9.49.1 没有本轮手机/模拟器运行验收。

## 对复刻研究的直接影响

当前可以稳定复用的仍是 8.72.0 运行资料：个人页折叠/吸顶、编辑资料三卡布局、设置页分组、背景预览的返回和权限空态。新版静态资料适合用来设计“候选模块边界”和“可替换的选图/上传接口”，不适合直接填入动画时长、输出尺寸、权限名称或服务器成功状态。

新版下一次手机测试应优先记录：同一账号两入口是否仍进旧 Activity、V2 是否实际出现、权限弹窗类型、选图网格与取消返回、裁剪初始缩放/拖动边界、上传失败与保存后刷新。未提供这些运行证据前，本页保持“静态局部对照”标签。

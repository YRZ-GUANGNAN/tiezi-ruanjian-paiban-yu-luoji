# 小红书手机端非购物功能研究

研究日期：2026-10-13。用途：为后续独立实现提供功能、数据、页面和动态逻辑依据。本文件保留 **8.84.5.5 安装包静态研究阶段**的事实与边界。后续已完成 8.72.0 的一轮手机交互观察，见[魅族 21 真机实测](新版研究/04-魅族21真机实测.md)及[滑动复刻规格](新版研究/05-滑动与导航复刻规格.md)；不要将两个版本的证据混写。没有制作复刻 App。

## 1. 最有用的结论

复刻这类产品的核心，是让同一条笔记在信息流、详情、搜索、个人主页、收藏专辑和聊天分享中保持一致，并正确处理加载、分页、媒体播放、用户互动与失败恢复。只复制页面外观无法覆盖这些关系。

本次能直接证实的关键点：

1. **内容与个人互动状态分开。** `NoteFeed` 同时包含 `liked` / `likedCount`、`collected` / `collectedCount`、`commentsCount`，以及图片、视频、作者、地点、话题和可见性字段；列表使用另一种 `NoteItemBean` 表示。它们不是一套静态卡片。〔C01、C02〕
2. **评论是带分页和发送状态的树形关系。** 模型包含根评论、回复目标、子回复列表和游标，也包含图片、本地图片路径、发送成功标记与重试计数。不能把评论做成一个永远加载全部内容的字符串数组。〔C06、C08〕
3. **图集使用横向分页吸附。** 一个详情实现明确配置横向 `RecyclerView`、`PagerSnapHelper`、缓存 3 项、关闭默认项目变更动画，并在滚动时更新图片指示和派发事件。〔M04〕
4. **按钮具有状态订阅与渲染分工。** 某详情 V3 分支订阅笔记状态，并设置计数、选中态及图形；其渲染方法将 Lottie 定位到最终帧。但继续追踪发现该分支先清零互动数据，不能直接认定它就是普通用户页面采用的实现。这个异常已保留为未知，而没有包装成正常业务规则。〔M01—M03、M42、M43、M46—M50〕
5. **页面会受配置影响。** 关注模块读取实验键 `image_update_style`；发布路由携带底部标签、编辑菜单、预加载、发布后提示等配置；搜索筛选页还存在设备形态适配分支。不能把某一次页面截图当成固定全局规则。〔M21、C44、M34〕
6. **收藏专辑与笔记合集需要分开。** `CommonBoardService` / `WishBoardDetail` 表示收藏板相关能力；另一组 `CollectionService` / `CollectionInfo` 包含合集、排序、集数等概念。两组代码不能因为都有 collect 字样就合并。作者合集的资格与当前入口仍待实测。〔C09、C46、C53、C55〕
7. **上传、草稿与发布是不同生命周期。** 本地编辑模型保留源文件、合成结果、图层、封面和视频片段；上传器有取消标记；官方还声明相册本地预载和视频服务器预上传。它们不能统一成一个“已保存”布尔值。草稿数据库与完整发布提交链仍未恢复。〔C48、C49、M22、F02—F04〕

以上是客户端证据及其工程含义；服务端推荐、审核、反作弊、流量分配和实时网络行为没有被还原。

## 4. 帖子、信息流与详情

### 4.1 同一条笔记有多种表示

`NoteFeed` 中可观察到：

- 身份和内容：`id`、`type`、`modelType`、`title`、`desc`、`text`、`user`。
- 媒体：`imageList`、`coverImageIndex`、`video`、`videoV1`、`videoV2`、`videoPlayInfo`、`music`。
- 互动：`liked`、`likedCount`、`collected`、`collectedCount`、`commentsCount`、`sharedCount`，以及格式化展示计数。
- 附加内容：`hashTag`、`ats`、`poi`、`ipLocation`、`privacy`、`noteStatement`、`coCreation`。
- 页面上下文：`cursor`、`cursorScore`、`position`、`isPreload`、`isSourceItem`、`needTransition`、`hasNoMore`。

这说明客户端对象既承载内容，也混有页面和展示上下文。**字段存在不等于每个字段都来自服务器**；不能把整个类直接视为后端数据库表。

列表 `NoteItemBean` 与详情 `NoteFeed` 分离，个人页又以列表差分方式更新项目。独立实现宜用稳定 `noteId` 连接各页面，在统一实体状态之上保留各列表自己的顺序和游标。此拆分是 C-建议。

### 4.2 关注流与发现流

`FollowFeedResponse` 包含 `cursor`、`hasMore`、`items`、`isEmptyResponse`、`needRecommend`、`totalFollowing` 等字段。`ExploreService`、`FollowFeedService`、`LocalFeedService` 是不同服务声明，附近还包含分类、顶部区域、地图入口及定位相关声明。〔C11、C12、C23、C31〕

可以确认“多种内容流并存”和“关注流具有分页/空内容相关数据”，但没有恢复它们的全部请求注解与响应处理。因此不能声称所有流共用相同游标、固定每页数量或纯时间排序。

`ExploreFeedPageConfigProvider.getTabModel()` 构造 `EXPLORE` 标签模型，证明一个发现页装配点；不能从单个标签推断完整底部导航顺序。〔M44〕

### 4.3 图集动态

`NoteDetailImageDisplayPresenter.m7()` 的明确设置：

1. 设置横向布局与 `PagerSnapHelper`。
2. 关闭嵌套滚动与 `SimpleItemAnimator` 的 change animations。
3. 设置 item cache size 为 3。
4. 滚动过程中计算当前图片位置，写入指示文本并发出索引变更事件。
5. 进入 dragging 状态、图片数大于 1 时，页码相关文本以 200 ms 淡入；随后调用 `t7(5000)`。
6. `t7` 清除旧回调，按传入延时安排 alpha 降到 0，时长 200 ms，然后执行隐藏辅助调用。

这些时长是**旧包代码中的配置值**。用户手指停留、再次拖动、主线程调度、系统动画设置与其他状态可能改变实际体验。不能直接写成“实测一定在停止滑动后 5 秒消失”。源码调用点位于淡入结束后。

图片手势接收器处理 DOWN、MOVE、UP、CANCEL 和多指事件，并切换父容器是否允许拦截。缩放方法对目标比例作上下界限制。部分方法有 JADX 重复代码/PHI 告警，因此没有据伪代码推断精确拖动阈值或极端多指行为。〔M06、M37〕

### 4.4 视频和自动滚动

自动滚动状态辅助器明确返回 `ACTIVATED`、`DEACTIVATED`、`DISABLED`；能力判断包含设备与页面条件，且检查平板分支。`activateAutoScroll` 仅在值改变时更新开关。〔M19、M20、M36〕

这支持“功能不可用”和“可用但用户未开启”应是不同状态。未恢复的混淆条件不能重新命名为某个确定入口；也不能把自动滚动等同于全 App 视频默认自动播放。

原生库里包含 React Native、Hermes、Reanimated 以及 redplayer、redpreload 等组件。这里只确认打包事实，不断言所有页面都是 RN，也不由库名推断播放器协议、预加载数量或网络策略。

## 5. 互动、评论与收藏

### 5.1 点赞和计数

详情 V3 按钮代码具有“接收状态→读取计数→选择文案或数字→切换图形”的结构。点赞渲染设置 Lottie 最终进度 `1.0`；收藏渲染设置 `selected` 并选取相应图片。〔M02、M42、M43、M46—M48〕

**发现的不一致必须保留：** `NoteDetailLikeBtnPresenter.c.accept` 在读取计数前调用 `p3(0L)`；追踪该 setter 确认它写入 `likedCount`，`o3(false)` 写入 `liked`。收藏分支同样通过 `L2(0L)` 写入 `collectedCount`，`K2(false)` 写入 `collected`。仅凭这些反编译结果无法判定这是特殊/未启用分支还是其他问题；不能据此声称真实页面每次更新都清零，也不能忽略这些语句后宣称已还原正常点赞流程。静态引用追踪得到 4 条引用，但不能证明运行启用。〔M42、M43、M49、M50、M53、M54、X01〕

视频按钮另有独立实现：`VideoFeedItemLikeBtnPresenter.u7` 直接使用点赞计数格式化；`v7` 依据选中状态、实验和自定义动画配置选择资源；其后续方法分别承接显示/播放处理。因此不能把前述 V3 异常推广到所有详情，更不能把单一动画文件视为全站统一配置。〔M55、M56、M59、M60〕

个人页的 `LikesRepository.d()` 根据目标状态选择请求，收到流中的结果后克隆列表项，再修改 `inlikes` 和 `likes`，生成差分并保存新列表。这个调用点能证明**收到结果后的列表更新**；它不证明整个 App 统一采用乐观更新。〔M12〕

继续追踪到 `mz6.h.e/f()` 后，确认它们分别调用 `CommonNoteService.dislikePost/likePost`，参数带 `discovery.` 前缀；方法内出现 `/api/sns/v1/note/dislike` 与 `/api/sns/v1/note/like` 字符串。只作旧包静态证据，没有请求这些接口。特别注意：`DISLIKE_NOTE` / `LIKE_NOTE` 事件在 `doOnTerminate` 中发布，**不能把该事件本身当成请求成功证明**，也不能把这里的取消点赞与推荐“不感兴趣”混为一谈。〔M39、M40〕

### 5.2 评论关系和发送状态

`CommentCommentInfo` 的关键关系：`id`、`noteId`、`rootCommentId`、`targetComment`、`subComments`、`subCommentCount`、`subCommentCursor`。一个子回复既需要归属根楼层，也可能回复楼层中的另一人。〔C08〕

同一模型还包含 `content`、`pictures`、`localPicPathList`、`atUsers`、`hashTags`、`isPicComment`、`isSendSuccess`、`status`、`retryCount`、`liked`、`likeCount`、翻译字段及 `enableInsertAnim`。

`CommentListRequestBean` 包含 `start`、`num`、`pageContext`、`sortStrategy`、`excludeCommentIds`、`topCommentId`、`showPrioritySubComments`、预缓存相关标记和超时参数。`CommentSortStrategy` 保存 `name`、`type`、`suffixName`，具体枚举值本轮未取到。〔C06、C38〕

服务声明分别提供根评论、子评论、发评论、点赞、取消点赞、删除、置顶、分阶段多媒体提交和预缓存等方法。**这些方法属于接口声明，本轮对接口方法的反编译返回 `body_status=not_available`，不是恢复了服务器实现。** 评论何时插入、排序如何改变、置顶资格、折叠数量、删除是否级联仍需真机。

图片评论上传回调可以进一步证实阶段分工：完成回调检查失败文件列表，非空时报告错误 `1003`；全部成功时整理 `FileUploadResult` 映射并通知后续处理。普通进度分支还把上传进度除以 2 交给上层，另有测试开关分支。因此媒体上传完成不等于评论已成功发布，也不能把单阶段进度直接当整体进度。〔M51、M52〕

### 5.3 三种不同的内容组织关系

| 关系 | 含义与证据 | 复刻时的注意点 |
|---|---|---|
| 点赞 / 收藏笔记 | 笔记 viewer 状态与总计数；官方声明有记录 | 单条笔记互动状态应跨页面一致 |
| 收藏板 / 收藏专辑 | 官方给出“我→收藏→收藏专辑”和仅自己可见；`CommonBoardService` 有创建、更新、移动、取消收藏、共享板等声明 | 收藏动作、专辑归属、专辑隐私是不同信息；共享板能力不等于所有账号有入口 |
| 合集 / 系列内容 | `CollectionService` 有 portfolio、加入/移除内容、排序等声明；`CollectionInfo` 有 `orderType`、`totalEpisodes`、`notePostLink` | 与收藏板保持独立对象；作者权限和入口需补测 |

收藏个人页会根据模式选择不同列表，替换相应笔记，再通过 `CollectNotesDiffCalculator` 计算差异。它证明这个位置有局部更新机制，不证明所有页面共享同一个实体仓库。〔M13、M35〕

## 6. 搜索、发布与个人页

### 搜索

`AliothServices` 包含笔记、视频笔记、用户、话题、群、POI、小程序等不同查询声明，以及结果筛选、热词和推荐词相关方法。商品/店铺查询排除。〔C13〕

`SearchFilterPanelFragment.onViewCreated()` 装配筛选根组件、绑定数据及动作，并依据在线配置和设备形态订阅变化。它证明筛选不是单纯静态菜单。当前版每个结果标签是否显示、筛选项的具体文案、建议词更新和搜索历史规则均待实测。〔M34〕

独立实现应至少把“输入中的词”“已提交的词”“结果类别”“筛选与排序”“当前请求版本”分开，避免用户已输入新词却被旧请求覆盖。此项是 C-建议，并非恢复到的原实现。

### 发布、编辑与草稿

官方证据给出首页“＋”、相册本地预载、拍摄/编辑权限、位置选取和视频提前上传开关。政策声称未发布或退出时删除临时上传；本轮未验证服务器执行。〔F02—F05〕

`PagePostNewNote` 与 `PagePostEditNote` 是不同路由对象。新建配置中有 `disablePreload`、`homeTabs`、`defaultOpenEditTab`、`imageEditPageMenu`、`videoEditPageMenu`、`saveAlbum`、`postSuccessToast`、`postSuccessShowShare` 等字段。这些是可携带的配置，不是已经确定的默认值。〔C36、C37、C44、C45〕

图像编辑模型区分图层、原始图层、本地路径、预览、合成结果、图片尺寸、滤镜、贴纸、Live Photo 视频文件等。视频编辑模型区分片段列表、封面、裁剪、音乐/音量、字幕、转场、章节、草稿更新提示等。字段中出现最短时长/片段上限常量名，**没有核验常量值，报告不填数字**。〔C48、C49〕

上传器取消方法会设置 `mCanceled` 并调用底层取消；另有上传超时广播注册。没有证据说明取消即删除服务器对象，也没有恢复完整发布 API、幂等机制、审核状态或草稿恢复过程。〔M22、M41〕

### 个人页

官方确认“笔记 / 收藏 / 赞过”和资料编辑字段；Manifest 同时存在自己、他人及浮层形式个人页组件声明。静态代码有点赞列表、收藏列表差分及草稿入口。〔F18、F19、C18、C19、C33、RES01〕

仍不能确定所有账号都显示全部栏目；他人的收藏隐私、获赞汇总口径、背景折叠、吸顶阈值、访问历史与列表恢复要逐项补测。独立实现的自己/他人视图应显式接收访问权限，而不是仅更换标题。

## 7. 消息、直播与其他手机功能

### 消息、私信、群聊

消息对象 `MessageBean` 包含 `id`、`uuid`、发收方、`createdAt`、`storeId` / `maxStoreId`、`hasRead`、`revoked`、`refMessage`、`isGroupChat`、`messageOperationStatus`。`content` 会进一步解析成带 `contentType` 的内容对象；会话对象又保存最近消息、时间与不同位置标记。〔C16、C42、C50、M23〕

这支持“消息身份、内容类型、撤回/引用、会话概览不是同一对象”。`hasRead` 存在仅证明客户端有该字段，**不证明对方能看到已读回执**。`storeId` 的精确顺序与持久化语义也未确定。

聊天处理方法中出现 long link 记录，并根据当前网络状态选择超时和配置，再交给另一个任务对象。它不揭示完整传输协议、重试规则或必达保证。〔M24〕

互动通知、私信、系统推送设置以及群列表得到官方资料支持。未读是否按条数或会话计数、打开即清零还是读到尾部才清零、群管理员资格、陌生人消息限制，都保留在验收清单。〔F15—F17〕

### 非交易直播

官方声明有直播观看、昵称头像、评论、点赞、在线信息、时长、连麦/提醒/浮窗等能力，并列出开播年龄及其他资格条件；部分直播可能开放 AI 总结。附近地图是否展示直播还受位置权限和精度影响。〔F25—F27〕

本次只完成其官方功能边界与包内入口线索。没有恢复直播播放、连麦协商、断线恢复与主持管理状态机。礼物、付费、钱包和带货成交不在范围内。

### 登录、权限、隐私、治理和长尾能力

官方明确给出评论/@控制、黑名单、举报、不感兴趣、调节推荐、关闭个性化推荐、通知设置、通讯录找人及帮助反馈等功能。与核心社区相邻的校园圈、翻译、AI、运动、限定回忆、未成年人模式和桌面小组件等，已在官方证据文档逐项登记，不能从政策列名推断本包中都可使用。

主导航只应呈现当前配置和权限下可用的入口；缺失入口不等于功能不存在。复刻范围可先关闭未明确实现的长尾入口，保留模块边界和后续扩展位置。这是实现建议，不是小红书原逻辑。

## 8. 动画资源与动态配置

包内静态解析了 32 个选定动画 JSON，保存路径、文件哈希、帧率、帧范围和尺寸。以下是资源的**内在时间轴长度**，计算为 `(op - ip) / fr`，不等于真机播放时长，也未全部建立到实际按钮的调用链。〔RES01〕

|---|---:|---|
| `doubleclick/double_click_like_v2.json` | 1500 ms | 文件名与资源事实；不能据此确认当前页双击播放它 |
| `view/double_click_like.json` | 1000 ms | 与上一个资源并存，实际选用条件未知 |
| `like/light_articel_like_confirm.json` | 约 1033.33 ms | 30 fps，31 帧范围 |
| `like/light_articel_like_cancel.json` | 700 ms | 不同于点赞资源长度 |

`LikeLottieInfo` 还包含明暗主题、单击/双击及不同尺寸版本字段；方法 `f(boolean)` 会选取一对 like/unlike 字符串，任一缺失则返回 null。详情按钮存在自定义资源与默认资源的选择分支。〔C21、M02、M25〕

## 9. 后续复刻如何使用这些成果

1. 以《02-页面状态机与复刻规格》作为独立实现的工程约定；其中建议状态、事件名和接口不是小红书私有协议。
2. 首先实现内容浏览、详情、图集/视频、赞藏评、个人页的一致性，再连接发布草稿、搜索和消息。完成这些闭环后再扩展群聊、附近与非交易直播。
3. 用《03-真机补测与验收清单》补全目前无法从安装包证明的行为，尤其是当前版本的导航、返回恢复、连续点击、权限拒绝和灰度差异。
4. 代码和资源事实通过《05-静态证据索引》追溯；接口声明无方法体、反编译告警和未验证行为均保留，不把“没有看见”写成“不存在”。

本阶段已形成可继续开发和补测的研究基线。**整个小红书的最新运行逻辑尚未完整还原**；精确视觉、所有账号能力、服务端逻辑和手机实测结果都没有冒充已完成。
